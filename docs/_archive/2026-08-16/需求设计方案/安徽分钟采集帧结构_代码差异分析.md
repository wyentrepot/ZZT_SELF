## 1. 0x00E2 — 采集任务配置（下行）

**代码位置**：`_parse_minute_config()` 第544~601行
**参考文档**：§2.1 采集任务设置下行报文（报文头固定长度16字节）

### 差异1：额外添加了"方向"字段，文档未定义

- **参考文档**：字节1 bit4~7 为**保留**
- **代码**：第559行添加了 `self._append(frame, "方向", "下行", ...)` 字段
- **影响**：低（仅展示性差异），但方向在0x00E2的协议定义中不存在，属于文档未定义的字段

### 差异2：报文头长度字段作为独立字段展示

- **参考文档**：报文头长度固定为16，拆分在字节0的bit6-7（高2位）和字节1的bit0-3（低4位）
- **代码**：第555行正确计算了header_len，但仅展示为一个"报文头长度"字段，没有按bit位拆分展示高2位和低4位
- **影响**：低（语义等价）

### 差异3：字节13的位布局解析正确，但展示方式不同

- **参考文档**：字节13有详细位布局图（bit0=启动/删除，bit1-3=协议类型，bit4-5=表类型，bit6-7=保留）
- **代码**：第574~584行，正确解析了各字段（`flag & 0x01`、`(flag >> 1) & 0x07`、`(flag >> 4) & 0x03`）
- **影响**：无（正确）

## 2. 0x00E2 — 采集任务设置上行应答（缺失）

**代码位置**：不存在
**参考文档**：§2.2 采集任务设置上行应答报文（报文头固定长度15字节）

### 差异4：上行应答报文完全未实现

- **参考文档**：§2.2 定义了完整的上行应答帧结构（STA → CCO），包含：
  - 报文头长度15字节
  - 电表MAC地址（字节6-11）
  - 任务号（字节12）
  - 启动/删除标志（字节13 bit0）
  - 结果位（字节13 bit1，0=设置成功，1=设置失败）
  - 保留（字节13 bit2-7）
  - 采集周期（字节14）
- **代码**：`_parse_minute_config()` 仅解析下行报文，无对应上行应答解析方法
- **影响**：中 — 无法解析STA回复CCO的配置应答帧

## 3. 0x00E3 — 采集任务数据读取（下行）

**代码位置**：`_parse_minute_read()` 第603~646行
**参考文档**：§3.1 曲线获取下行报文（报文头固定长度20字节）

### 差异5：协议类型字段位宽错误

- **参考文档**：字节6 bit0~2，**3bit**（值：2=645协议，3=698协议）
- **代码**：第625行 `proto_type = business[6] & 0x0F` 使用了 **4bit** 掩码
- **影响**：**高** — 当电表类型（bit3-4）非零时，协议类型字段会被错误地包含电表类型的bit3，导致协议类型值错误（如电表类型=1时，协议类型会被多读bit3，从2变成0x0A或0x0B等非法值）

### 差异6：电表类型字段位宽和偏移错误

- **参考文档**：字节6 bit3~4，**2bit**（值：0=单相，1=三相，2=其他表计）
- **代码**：第626行 `meter_type = (business[6] >> 4) & 0x01` 使用了 **1bit** 掩码，且偏移右移了4位
- **影响**：**高** — 正确应为 `(business[6] >> 3) & 0x03`。当前代码：
  - 只读取bit4（1bit），漏掉了bit3
  - bit3已被协议类型错误地读取（见差异5）
  - 导致电表类型只能区分0和1，无法表示2（其他表计）

### 差异7：冻结时刻未按小端BCD解码，直接显示原始字节

- **参考文档**：§1.2 和 §3.1 明确要求冻结时刻为**小端字节序BCD码**，从报文中的偏移读取时需倒序
  - 字节偏移14~19含义：HH、MM、DD、MM、YY、SS（小端存储）
  - 实际值：`20YY-MM-DD HH:MM:SS`
- **代码**：第643~646行
  ```python
  freeze = business[14:20]
  freeze_str = "-".join(f"{b:02X}" for b in freeze)
  ```
  直接将6个字节按原始顺序拼接显示，如 `"26-07-31-07-00-55"`，而不是解码为 `"2026-07-31 07:55:00"` 格式
- **对比**：`_parse_minute_report()` 中的主动上报格式（第502~510行）正确实现了小端BCD反转解码，说明0x00E3的冻结时刻解码被遗漏了
- **影响**：**高** — 显示的冻结时刻值完全不可读，无法正确反映实际时间

### 差异8：字节6的注释与文档不一致

- **参考文档**：字节6 bit5~7为**保留**
- **代码**：第607行注释写的是`协议类型(4)+电表类型(1)+保留(3)`，但实际参考文档是`协议类型(3)+电表类型(2)+保留(3)`
- **影响**：低（仅注释，不影响执行）

## 4. 0x00E4 — 格式一：并发抄读格式（未实现）

**代码位置**：`_parse_minute_report()` 第414~422行
**参考文档**：§4.1 格式一：并发抄读格式（响应CCO抄读，报文头固定长度23字节）

### 差异9：并发抄读格式（启动位=0）未展开业务字段

- **参考文档**：§4.1 定义了完整的23字节报文头，包含：
  - 协议版本号、报文头长度、方向位
  - 报文序号（32bit）
  - 协议类型（3bit）+ 电表类型（2bit）+ 响应结果（3bit）— 字节6
  - 源MAC地址（48bit）— 字节7-12
  - 任务号（8bit）— 字节13
  - 冻结时刻（48bit，小端BCD）— 字节14-19
  - 报文条数（8bit）— 字节20
  - 转发数据长度（16bit，小端）— 字节21-22
  - 报文内容（变长）
- **代码**：第414~422行，当 `start_flag != 1` 时直接跳转到 `_parse_generic_business()`
  ```python
  frame.warnings.append("并发抄读格式（启动位=0）本期仅展示原始业务报文并扫描内嵌帧")
  self._parse_generic_business(frame, business)
  ```
- **影响**：**中** — 所有格式一的字段都未被解析，仅展示原始十六进制

## 5. 0x00E4 — 格式二：主动上报格式（正确）

**代码位置**：`_parse_minute_report()` 第389~542行
**参考文档**：§4.2 格式二：主动上报格式（STA主动上报，报文头固定长度8字节）

### 差异10：转发报文内容中的"任务数"字段被跳过

- **参考文档**：§4.2.1 转发报文内容格式，字节0 bit0~4为**任务数**（5bit，最大31个），bit5~7为保留
- **代码**：第472~474行
  ```python
  self._append(frame, "前导字段", f"0x{forwarded[0]:02X}", ...)
  ```
  直接将forwarded[0]作为"前导字段"（占位字节）展示，没有解析其中的任务数字段
- **说明**：文档本身注明了"前导字节在方案文档中未定义，实现中作为源MAC前的占位字节"，但§4.2.1 又定义了此字节的任务数结构，两者存在矛盾
- **影响**：低（文档本身对前导字节的定义存在矛盾）

### 其他字段 — 正确

- 源MAC地址 ✓
- 任务号 ✓
- 协议类型（`packed & 0x07`，3bit）✓
- 电表类型（`(packed >> 3) & 0x03`，2bit）✓
- 响应结果（`(packed >> 5) & 0x07`，3bit）✓
- 冻结时刻（小端BCD反转解码）✓ — 正确实现了 `freeze[::-1]` 反转
- 报文条数 ✓
- 数据长度 ✓
- 数据内容嵌套解析 ✓

## 6. adapter_10376 缺少 0x00E2/E3/E4 报文ID注册

**代码位置**：`parser_lib/adapters/adapter_10376/__init__.py`
**参考文档**：全局

### 差异11：_DUALMODE_MESSAGE_NAMES 字典缺少三个分钟采集报文ID

- **adapter_dualmode** 的 `_MESSAGE_NAMES`（第56~58行）正确注册了：
  ```python
  0x00E2: "采集任务配置",
  0x00E3: "采集任务数据读取",
  0x00E4: "采集任务数据上报",
  ```
- **adapter_10376** 的 `_DUALMODE_MESSAGE_NAMES`（第48~73行）**没有**这三个报文ID，仅到0x00A4为止
- **影响**：低（当前10376适配器中 `_parse_dualmode_43()` 只是用 `_DUALMODE_MESSAGE_NAMES.get(msg_id, '未知报文ID')` 做展示，不影响解析逻辑，但展示时分钟采集报文ID会显示为"未知报文ID"）
