## 2. 串口映射明细（2026-08-18 实测 / 2026-08-19 复核）

串口均通过 **usbip over USB/IP（`vhci_hcd`）** 映射进 WSL。2026-08-19 起新增 CH342 → `/dev/ttyACM0/1`（其余为 `/dev/ttyUSB*`）。

### 2.1 当前映射（2026-08-19 复核）

```text
/dev/ttyACM0  ->  /devices/platform/vhci_hcd.0/usb1/1-1/1-1:1.0/tty/ttyACM0   (CH342 Port A = COM8 = CCO)
/dev/ttyACM1  ->  /devices/platform/vhci_hcd.0/usb1/1-1/1-1:1.2/tty/ttyACM1   (CH342 Port B = COM9 = STA)
/dev/ttyUSB0  ->  /devices/platform/vhci_hcd.0/usb1/1-2/1-2:1.0/ttyUSB0/tty/ttyUSB0   (CP210x = COM4 = 侦听口)
/dev/ttyUSB1  ->  /devices/platform/vhci_hcd.0/usb1/1-3/1-3:1.0/ttyUSB1/tty/ttyUSB1   (CP210x = COM24 = 交互口)
```

- vhci 端口路径 `1-1 / 1-2 / 1-3` 对应 Windows 侧**物理 USB 端口位置**（与设备管理器中的端口位置一致）。
- **2026-08-19 变更**：CH342（1a86:55d2）成功 attach 到 WSL，枚举为 `/dev/ttyACM0`（CCO=COM8）、`/dev/ttyACM1`（STA=COM9）。旧记录中 COM4=1-1、COM24=1-2、COM23=1-3 的排布已变为 COM4=1-2、COM24=1-3、CH342=1-1——**物理端口排布可能变化，真机操作前须按本节复核**。
- usbip 映射**不传递** `ID_SERIAL` 等属性，`udevadm` 查不到序列号；区分两个 CP210x（COM4 vs COM24）需看 Windows 设备管理器物理端口位置（§4）。
- CH342 双串口：**Port A=interface 0=COM8(CCO)，Port B=interface 1=COM9(STA)**，Linux 按 interface 顺序枚举为 ttyACM0/ttyACM1，顺序固定。

### 2.2 历史映射（2026-08-18，记录留档）

```text
/dev/ttyUSB0  ->  /devices/platform/vhci_hcd.0/usb1/1-1/1-1:1.0/ttyUSB0/tty/ttyUSB0
/dev/ttyUSB1  ->  /devices/platform/vhci_hcd.0/usb1/1-2/1-2:1.0/ttyUSB1/tty/ttyUSB1
/dev/ttyUSB2  ->  /devices/platform/vhci_hcd.0/usb1/1-3/1-3:1.0/ttyUSB2/tty/ttyUSB2
```

### 串口角色 ↔ 用途

| 设备 | 角色 | 波特率 | 用途 / 对应代码 |
|---|---|---|---|
| `/dev/ttyACM0` (COM8) | CCO 日志口 | 115200 | CH342 Port A，模块日志实时采集（`module_log`，映射 id=`cco-main`） |
| `/dev/ttyACM1` (COM9) | STA 日志口 | 115200 | CH342 Port B，模块日志实时采集（`module_log`，映射 id=`sta-main`） |
| `/dev/ttyUSB2` (COM23) | 烧录口 | XMODEM（导航 9600→传输 115200→恢复 9600） | CCO 固件烧录，见 §3；命令 `flash_module.py --port /dev/ttyUSB2 ...` |
| `/dev/ttyUSB1` (COM24) | 交互口 | 9600 | 模拟集中器 ↔ CCO 交互；任务文件 `apps/workbench/scenarios/tasks/anhui_minute_collect.json`（`port: "COM24"`, `baudrate: 9600`） |
| `/dev/ttyUSB0` (COM4) | 侦听口 | 115200（只读） | 侦听台采集帧落库（`apps/listener`），Run 只读索引库取帧，不抢串口 |

> ⚠️ 注意 1：08 手册 §5 的命令示例写 `--port /dev/ttyUSB0`，但按其环境速查表 COM24（交互口）应映射为 `/dev/ttyUSB1`，且任务文件 `port: "COM24"`。**交互验证的端口应以 COM24 映射为准（`/dev/ttyUSB1`）**，§5 示例疑为笔误，真机执行前须复核。
> ⚠️ 注意 2（2026-08-19）：本轮实测中 `/dev/ttyUSB2`（COM23 烧录口）**未出现在 WSL 侧**（usbipd 显示 COM23 仅 Persisted 未 Attached）。烧录前须先映射 COM23，否则用 `--port /dev/ttyUSB2` 会找不到端口。

## 5. 操作守则（不轻易动硬件）

### 5.1 可自行执行（安全，只读/无副作用）

- ✅ `ls -la /dev/ttyUSB* /dev/ttyACM*` — 查看串口是否映射
- ✅ `udevadm info --query=path --name=/dev/ttyUSBx /dev/ttyACMx` — 查看 vhci 端口路径
- ✅ `python3 apps/module_log/flash_module.py --selftest` — 烧录模块 CRC 自检
- ✅ `python3 apps/module_log/flash_module.py --list-ports` — 列出可见端口
- ✅ `python3 apps/module_log/flash_module.py --port /dev/ttyUSB2 ... --dry-run` — **dry-run 校验参数（不写固件）**
- ✅ 无硬件自检：`python3 -m pytest libs/sim_concentrator/ -q`（53 passed）

### 5.2 须人工授权（写设备 / 不可回退 / 影响物理链路）

- ⛔ **真机烧录**（`flash_module.py` 不带 `--dry-run`）— 写固件，不可完全回退
- ⛔ **COM24 交互验证**（`sim_concentrator verify ... --port ...`）— 写设备、改采集任务配置
- ⛔ **串口映射/恢复**（`串口映射.bat` 切换 Windows/WSL 串口）
- ⛔ 任何 `--port` 指向真实串口且不带 dry-run 的写操作

> **原则**：拿不准是否安全的操作 = 视为需人工授权。文档/代码可随便看，硬件写入一律先请示。
