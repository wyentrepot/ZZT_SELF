## 3. 已打通链路与实测证据

### 3.1 CCO ↔ 模拟集中器（1376.2 本地总线）✅

- CCO 上电后 bpsCheck 事务循环发 14H-F2 时钟请求（实测帧 `68 0F 00 C3 00 00 40 00 00 FB 14 02 00 16 16`，AFN=14 Fn=F2，seq 递增）。
- simcon 以 verify 任务（recv_only + 14-F2 clock/echo 应答规则）应答后，CCO 日志出现 **`bpsCheck affair over`**——本地总线判定成立（`gSysPara.cac.local_rx_ok=1`，判据在 CCO 源码 `com_port.c:371`，收到任意 LFRAME_VALID 本地帧即置位）。
- 10H-F2 查询从节点档案实测成功，返回 3 条档案：`103827699719`、`006046130926`、`030000000000`。
- ⚠️ simcon 常驻自动应答器（`_auto_ack_responder`）刻意不回 14-F2（防回环），**bpsCheck 的应答要靠带 responder 规则的 verify 任务**；且 14-F2 走 local 单 68 分支时 `userdata_builder:"clock"` 未实现（发出空数据帧，CCO 不认），实测用 `format:"local" + echo` 可通过。**建议给 sim_concentrator responder 的 local 分支补 clock 实现。**

### 3.2 STA 最新固件烧录 ✅

- `cd /home/H_STA/02/sta && make sta_venus2m -j8` 构建成功（安徽-2601-STA-sv001401-260509-isv090006-idate260914）。
- 经 STA 日志口 XMODEM 烧录：`python3 apps/module_log/flash_module.py --port /dev/ttyACM0 --bin <iap_*.bin> --baud-plan 115200`，**BURN SUCCESS**（366 包 / 374544 字节）。
- 新固件实测变化：日志显著增多；绑表状态机（`aps_addrmap_state.c`）启动，实测底座口出现 645 读地址帧（`turn:1 pos:26/27 baudrate:2400 E DLT645/698_CMD` 等组合轮询）；网络发现正常（`recv bcn, from HPLC, NID=0x6bf43f`，能听到 CCO 及多个 STA 的 beacon）。

### 3.3 STA 绑表扫掠帧实测到达底座口 ✅（部分）

底座口裸口嗅探曾完整捕获 STA 的 645 读地址探测帧（与 STA 源码 `aps_addrmap_state.c` 内置帧一致）：

```
FE FE FE FE 68 99 99 99 99 99 99 68 13 00 79 16   ← 13H 读地址，99×6 广播（07 版）
FE FE FE FE 68 AA AA AA AA AA AA 68 13 00 DF 16   ← 13H 读地址，AA×6 广播
```

## 4. 阻塞根因（已定位，待解）

### 4.1 STA 载波功放被功耗管控关闭（入网发不出请求）

- STA 启动日志：`power(8) greater than level4, 60min later to set hplc power` → `nwk_init,hplc_pwr=0`。
- 源码依据（`nwk_intf.c:206-222`）：flash 参数 `hplc_pwr=8 > 4` 触发 `power_update_init()`，**HPLC 功放置 0 长达 2400s**，到期后 `power_update_poll()` 才按参数 8 设置 TGAIN（日志将出现 `hplc power set succ`）。
- 后果：STA 能听 beacon（RF 正常，rf_pwr=48）并进入 state 2（已发现网络），但关联请求发不出去，CCO 侧 `onnet=0` 且无 `recv assoc_req`。
- 解法（任一）：等待上电后约 40 分钟；或改 STA flash 参数（`staPara_hplc_pwr_set` ≤4，可由 CCO 下发对应设置帧或控制台/工具写参数区）；新固件重烧**不会**重置该参数（参数区独立）。

### 4.2 底座口桥的固定波特率/校验 vs STA 扫掠组合错配

- Windows 桥 CP210x 固定 115200 8N1 时，STA 扫掠的 2400E/9600E/1200E 等位置到 WSL 全是坏字节（奇偶位被当停止位、约半数字节被丢）；只有扫掠走到 **115200** 的位置帧才完整。
- 已将 COM24 桥改为 **115200 8E1**（匹配扫掠全 E 组合）。待 STA 重新扫掠验证：115200-E-645 位置应能被虚拟电表完整应答，绑定成功后 STA 记忆该波特率（`REMAP_BPS_DEF`）。
- 注意：本环境桥是固定波特率的透明管道，**STA 的绑表扫掠最终会落在与桥一致的 (115200, E) 上**，与"STA 默认 9600,8,N,1"的预期不符是桥配置所致，不是电表能力问题；若要求落在 9600/N，需把桥 COM24 改为 9600 8N1 并让 STA 扫掠命中该组合（其扫掠表含 9600 与 N 组合位）。

### 4.3 socat 桥的 pts 软链漂移

- 桥进程每次重启/重连，socat fork 子进程新建 pts，`/dev/ttyUSB*`、`/dev/ttyACM*` 软链失效或悬空；多次出现"进程还握着旧 pts、新数据在新 pts"导致的静默丢帧。
- 处置：已用脚本按 TCP 端口→pid→pts 动态重建软链（`/tmp/fix_links.sh`，建议固化进 `tools/scripts/`）；**任何桥重启后必须重建软链并重启占用方进程**。
