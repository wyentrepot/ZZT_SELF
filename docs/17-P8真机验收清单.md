# 17-P8 独立真机验收清单

> 文档性质：**只列清单、不实际执行**的独立真机验收项（P8 交付门最后一环）。
> 生成日期：2026-08-24
> 依据：`docs/_archive/2026-08-24/P3-P6交接清单.md` §3 P8、P1-P6 实现（ADR-30~35）。
> 前置：真实串口环境（COM4 侦听 / COM8 CCO 日志 / COM9 STA 日志 / COM24 模拟集中器，见 `docs/15-硬件资源速查.md`）、物理映射模板 `config/serial_ports.json`、已打包 `dist/工作台/工作台.exe`。
>
> ⚠️ 以下所有步骤**不得在本清单外自动执行**；真实串口启动、发送、烧录必须在当次操作由用户**单独明确授权**后进行。

## 1. 前置与环境核对

- [ ] 真机环境可用：4 个串口（COM4/COM8/COM9/COM24）全部枚举可见（`/api/serial/ports` 与 `port_details` 一致）。
- [ ] `serial_ports.json` 物理映射与真机一致；`mapping_error` 为空。
- [ ] 打包产物 `工作台.exe` 启动后 `runtime/` 已生成，`serial_ports.json` 已复制到 exe 同级 `config/`。
- [ ] 默认 Profile 四槽均为 `enabled:false`，启动不自动打开任何串口。

## 2. 四槽 Save / Apply（P3+P4 串口 Profile）

- [ ] **保存（PUT /api/serial-profile）**：四槽分别配置启用/映射/波特率并保存；刷新后持久化（原子写入 `runtime_dir`）。
- [ ] **一键应用（POST /api/serial-profile/apply）**：应用后按固定顺序（侦听台→CCO→STA→模拟集中器）逐槽状态符合预期（`started/reused/stopped/unchanged/skipped/failed`）。
- [ ] **刷新状态（GET）**：应用后各槽 `status`/`占用`/`应用结果` 反映真实串口状态。
- [ ] 重复应用相同 Profile：已运行槽返回 `unchanged/reused`，不重复打开串口。
- [ ] 禁用槽应用：仅停止 `托管-` 前缀会话，**不影响**人工动态会话。
- [ ] `serial_ports.json` 只读：应用后该文件不被修改（Profile 独立存储）。

## 3. 页面保活（P5 导航 + iframe）

- [ ] 一级分组导航（验证/设备/维护）切换：已加载 iframe 不重设 `src`，不重载页面。
- [ ] hash 路由：切页后 `location.hash` 正确；刷新/前进后退恢复到对应页。
- [ ] 折叠/抽屉：桌面端侧栏折叠为图标栏；窄屏抽屉可键盘关闭（Escape/遮罩/焦点回归）。
- [ ] **运行会话保持**：串口会话运行中切页/刷新后，会话不被 stop（listener 状态优先恢复）。

## 4. 部分失败（P4 applier + P6 配置页）

- [ ] 人为制造单槽失败（如串口被占用/拔出）：单槽 `failed`，后续槽继续，不回滚成功项。
- [ ] 配置页部分失败：保留成功槽状态，错误摘要可聚焦（`tabindex`+focus）。
- [ ] 重复映射：两个槽选同一映射时 apply 前阻止，零副作用。

## 5. 实时 observation 起始边界（P1+P2 AI 观察）

- [ ] module live `observe`：从 `start=now` 监听，`regex`/`loghook_rule`/`sequence`/`not_seen` 各匹配一次真实日志。
- [ ] `not_seen` 逾期且无可信行到达时间：返回 `timed_out + condition_met=false + reason=live_window_unverified`（不误报成功）。
- [ ] listener `cursor_range`：按 `index_id + frame_id` 深链观察首尾/越界/裁剪；`wait` 单次 ≤30s、终态即停。
- [ ] `observe-workbench-logs` 技能：默认 dry-run 零 HTTP；`--execute` 仅对既有 session/index 生效。
- [ ] Token：仅 `WORKBENCH_AI_TOKEN` 生效；脱敏不泄漏；无控制操作命令。

## 6. 烧录后因果验证（P2 观察 + 真机）

- [ ] 烧录完成后：module 日志能观察到 bootloader → 应用启动关键日志（`loghook_rule` 命中）。
- [ ] 烧录前后状态可区分：`observe` 在烧录前后窗口能取到因果证据。
- [ ] CCO/STA 烧录后交互（698/分钟采集）行为与预期一致（结合既有 task 验证）。

## 7. 通过标准

- [ ] 2~6 全部项通过（或每项如实记录未验证原因）。
- [ ] 结果回填：更新 `docs/17-P8真机验收清单.md` 勾选状态 + `docs/04-任务安排.md` P1-P8 状态表 + 交接报告。
- [ ] 真机验证项全部完成后，P8 才算正式交付门关闭；P7（目录整理）仍为独立后续项。
