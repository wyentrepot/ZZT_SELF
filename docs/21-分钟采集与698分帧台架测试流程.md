## 5. 698 分帧（链路层分片）测试流程

何时需要本节：验证「表端把一个长 APDU 拆成多帧发，STA 逐片确认、收齐合并、正常落盘」。

**判分帧三条件（缺一即非分帧，02卡 §2.4/§2.7；经验索引 2026-11-03）**：
① C 域 bit5=1（分帧标志）；② 用户数据开头有 2B 分帧格式域；③ 有起始/中间/末尾配套片段。
（反例：com25 日志 42 帧 C=0xE3 的对时响应 bit5=1 但无格式域、无分片，属发送端异常置位，不是分帧。）

**分帧格式域（2B）**：bit15..14=类型（`00` 起始 / `10` 确认 / `01` 末尾 / `11` 中间），bit13..0=帧序号 0~4095。
线上字节序：byte0=seq 低 8 位；byte1 高 2 位=类型（起始 00 / 中间 C0 / 末尾 40）+ 低 4 位=seq 高位（02卡 §2.7，STA 按 `type=(b1&0xC0)>>6` 解析）。

**链路层帧布局（与台架证据帧逐段同构）**：
```
68 | L(2B LE，=自身2B+C..FCS=总长-2) | C=0xE3(表→STA分帧应答) | SA 7B(05+6B BCD地址低位在前) | CA |
HCS=fcs(b[1:12]) | 分帧格式域2B | APDU片 | FCS=fcs(b[1:-3]) | 16
```

**操作序列**：
1. 置 OAD missing（脑静默，把应答权让给注入）：
   ```bash
   curl -X POST http://127.0.0.1:8790/api/simeter/oad -H "Content-Type: application/json" \
     -d '{"entries":[{"oad":"20000201","missing":true,"length":2},{"oad":"20010201","missing":true,"length":2}]}'
   ```
2. 构分帧帧：`python3 tools/scripts/minute_collect/build_split_frames_full.py`（完整 APDU → 起始/中间/末尾三片，参数以 `--help` 为准；由 retest_2330 轮 `build_frames.py` 沉淀，自校验 HCS/FCS 与拼回一致性）。
   **APDU 必须与任务 OAD 匹配！** 23:30 轮已验 APDU：`850201022000020101110120010201011102`
   （85 02 01 + di_cnt=02 + OAD 20000201+01+1101 + OAD 20010201+01+1102）。22:30 轮把 OAD 写成 `22000201`，ACK/合并都对但**不落盘**（§9 坑 1）。
3. 后台守望注入：`python3 -I tools/scripts/minute_collect/watch_inject.py <frames.txt> [timeout_s]`
   （等 simeter /frames 出现 STA 请求 `68310043` → +300ms 注首片 → 片间隔 150ms；单轮触发，完成即退，时间线落 stdout）。
4. 等冻结边界自动触发，STA 日志验证三步（23:30 轮实证，`/tmp/req006_evidence/retest_2330/sta_log_2330_round.txt`）：
   - **ACK**：`[RX] 68110063 05…00e462 0080 d678 16`（起始片 ACK，格式域 `0080`=类型10+seq0）→
     第二帧 `…0180…`（中间片 ACK，seq1）。确认帧固定 19B、类型 10、**seq 透传**、DIR 取反（STA `mclt_pack_split_confirmation`）；
   - **合并**：末尾片（格式域 `0240`）后不回 ACK，缓存拼回完整 APDU（分帧缓存 2048B，超限清缓存走重抄）；
   - **落盘**：`recv 698 data …1101/1102` → `Freeze data for task 1 stored successfully`（23:30:02.328 实证）。
5. **完成恢复 OAD missing=false**（重放 §4 第 1 步的 data_hex 版本），否则下一轮脑一直静默。
6. 分帧冻结数据被 CCO 11E3 补采读出的端到端：观察窗口内 CCO 未自主发起 11E3（详见 §7 当前状态），按 §7 判定方法在后续轮次补验。
7. 已验帧组（send_hex 注入用）：`/tmp/req006_evidence/retest_2330/frames_new.txt`（23:30 轮三片，全链路 PASS）。
   `/tmp/split_frames_v2.txt`（22:30 轮三片）**仅作帧布局基准，勿直接复注**——其 APDU 与任务 OAD 不匹配，ACK/合并正常但不落盘（坑 1）。

## 6. 698 分块（服务层 85 05 / 05 05 拉块）测试流程

何时需要本节：验证「STA 收到 85 05 分块应答后回 05 05 逐块拉取、末块拼装落盘」的完整闭环。

**帧口径（以 STA 源码 `mclt_handle_get_response_next` + 21:45 轮已验帧为准）**：
- 表端 85 05 应答（DL/T 698.45-201X §6.3.8.2.5 表76「读块」）：外层明文安全包装 `90 00 <内层长度>` +
  内层 `85 05 | PIID-ACD(1B) | lastblock(1B, 0/1) | block(2B 低字节在前) | CHOICE(01=数据/00=DAR) | 本块数据`。
  **lastblock 在 block 之前**（源码常量 `MCLT_698_8505_HEAD_LEN=5` 的注释原文）；块序号从 0 起，上限 4095（表76 long-unsigned）。
- STA 对**每个非末块**回 `05 05` GetRequestNext（PIID + 最近正确接收块号，2B；02卡 §3.2；图24 每块必确认），

- **末块不确认**：直接把累计缓冲前置 `[85 02][PIID]` 就地重组为非分帧安全响应帧交既有单帧路径落盘。

- 差错处理（STA 侧行为）：CHOICE=[0] 携 DAR 即终止本轮（拉块相关 DAR：9 数据块不可用 / 10 分帧传输已取消 / 11 不处于分帧传输状态，02卡 §5.4）；块号≠期望(上次+1)、超 4095、超长溢出均终止，日志 `8505 block num err` / `8505 acc overflow`。

1. 置 OAD missing=true（同 §5 第 1 步，关脑自动应答，给 STA 留 2.5s 应答窗）；
2. 构帧/编排：`python3 tools/scripts/minute_collect/build_8505_block.py`（离线构帧）+

## 7. 11E3 补采与 06H-F230 判定

何时需要本节：验证「STA 冻结落盘的数据，CCO 能经 11E3 自主补采读走并以 06H-F230 上报入库」。

- **11E3 不可由 simcon 交互口注入**（README 坑 1，2026-11-03 台架×2 实测）：11E3 由 CCO 在冻结后约 9min 起**自主发起**（本轮实测：20:14:25 补 19:45 冻结、20:29:24 补 20:00 冻结，滞后受 CCO 补抄轮询影响，等不到就再跨一轮边界）。
- **判定抓法（词边界锚定，防 16 进制数据误报）**：
  ```bash
  grep -aiE "(^|[^0-9a-f])11e3" <sta日志文件>
  ```
- **成功链**：11E3 下行（携带补抄冻结时刻）→ STA 响应带数（内层 698 `85 02 01 <di_cnt> …`）→
  06H-F230×N 入 simcon store（`collect_time`=冻结时刻，本轮 47B/条）。20:14 轮实证：补 19:45 冻结 → F230×3 入库。
- **缺数链**：STA 无数 → 11E3 上行载荷 `0000` → **无 F230 上报**（行为自洽，不算故障）。20:29 轮实证：20:00 轮拉块失败未落盘 → 补抄载荷 0000。
- **当前状态**：观察窗口（23:30–00:02，含 23:45/00:00 两轮正常冻结）内 CCO 未自主发起 11E3（自 20:59 后无任何 11E3）。req006 收口以 §5 直接判据为准；本节两条链的判定方法供后续轮次复用：有数→F230（collect_time 对准冻结时刻）或缺数→无 F230，两者皆自洽；「无 F230 且 STA 也无该冻结数据」不能记失败，先查 §4 的 Freeze stored 有没有发生。

## 9. 踩坑清单（编号引用，含来源轮次）

何时需要本节：动手前扫一遍；出症状先来这里对号。

1. **注入帧 APDU 内容必须匹配任务 OAD**（22:30 轮 OAD 写成 `22000201` → ACK/合并都正常但数据不落盘；23:30 轮修正为 `20000201` 后 PASS）。构帧前先 `mclt_list_query.py` 核对任务 OAD。
2. **SA 域是 7B 不是 6B**（README 坑 3）：首字节 0x05 是地址长度/类型头，后跟 6B BCD 地址低位在前；少算 2B 会把 HCS 之后全体错位（第一版构造器踩过）。
3. **分帧格式域字节序**（HANDOVER 坑 1）：类型在 **byte1 高 2 位**（起始 00/中间 C0/末尾 40/确认 80），byte0 是 seq 低 8 位；写成 `00 85` 会被 `(b1&0xC0)>>6` 判成 ACK 类型。
4. **HCS/FCS 覆盖窗与 L 值**：HCS=`fcs(b[1:12])`、FCS=`fcs(b[1:-3])`（`libs/parser_lib/adapters/adapter_698`）；L=自身 2B + C..FCS（=总长-2），**先定最终 L 再算校验**，否则校验窗里是旧 L 必挂。
5. **simeter 脑现可自动应答 698 OAD**（REQS-0037 v1.1.0；HANDOVER 里「不会自动应答」已过时）——注入场景**必须先置 missing=true**，否则脑 ~11ms 抢答，注入永远输。
