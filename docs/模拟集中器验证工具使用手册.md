# 模拟集中器验证工具使用手册

> sim_concentrator —— 在侦听台仓库内新增的模拟集中器上位机模块。
> 模拟 1376.2（Q/GDW 10376.2）集中器模块，与 CCO/STA 模块通信：
> 主动下发帧、接收并解析模块上行帧、按规则主动应答、执行 AI 传入的验证任务并返回结论。
> 设计决策见 `DECISIONS.md` ADR-10。

---

## 一、它解决什么

AI（或脚本）在**烧录代码之后**，把"需要验证的方法"作为一份**验证任务 JSON** 交给本工具；
工具在串口上自动执行：下发帧 → 接收 → 匹配 → 解析 → 逐步判定，最后返回**结构化结论 JSON**
（每步 Pass/Fail + 原因 + 汇总结论）。全程无需人工操作 Web 界面。

三大能力（对应需求）：
1. **模块上行数据，模拟集中器主动应答**——`responder.py` 内置应答规则表，收到上行帧自动回下行帧。
2. **模拟集中器下发，匹配接收并解析**——`matcher.py` 按 AFN/信封字段/嵌套 645/698 字段断言，
   `frame_codec.decode_frame` 解出结构化字段。
3. **插入验证方法自动化流程**——`runner.py` 顺序执行任务步骤，`api.py`/`cli.py` 提供 REST / CLI 入口。

## 二、目录与依赖

```
sim_concentrator/
├── __init__.py        # 模块声明
├── frame_codec.py     # 帧编解码层（构帧/切帧/解析 → dict）
├── serial_io.py       # 可读写串口通道（读线程切帧 + 写锁发送）
├── responder.py       # 应答引擎（内置模板 + 用例覆盖）
├── matcher.py         # 接收帧匹配与断言
├── runner.py          # 验证任务执行器（闭环核心）
├── api.py             # FastAPI 子应用（REST 入口）
├── cli.py             # 命令行入口
└── test_*.py          # 单元测试（35 用例）
```

依赖：复用仓库内 `parser_lib`（`adapter_10376`）、`pyserial`、`fastapi`、`uvicorn`。无新增第三方。

## 三、快速开始

### 3.1 CLI 验证一个任务

```bash
# 列出内置应答规则
.venv\Scripts\python.exe -m sim_concentrator responders

# 列出可用串口
.venv\Scripts\python.exe -m sim_concentrator ports

# 执行验证任务（JSON 输出）
.venv\Scripts\python.exe -m sim_concentrator verify task.json --port COM3 --baud 115200 --json
```

退出码：结论为 `pass` → 0；`fail` → 1（便于 AI 脚本判断）。

### 3.2 REST API

```bash
# 独立启动（端口 8781）
.venv\Scripts\python.exe -m sim_concentrator.api
```

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/simcon/status` | 串口/模块状态 |
| GET  | `/api/simcon/ports` | 可用串口 |
| GET  | `/api/simcon/responders` | 当前生效应答规则 |
| POST | `/api/simcon/open?port=COM3&baudrate=115200` | 打开串口（长驻） |
| POST | `/api/simcon/close` | 关闭串口 |
| POST | `/api/simcon/verify` | 执行验证任务（body 为任务 JSON） |

也可把 `sim_concentrator.api.create_simcon_app()` 挂载到侦听台 `listener/app.py` 的 `create_app()`。

## 四、验证任务 JSON 格式

```json
{
  "id": "verify.add_node",
  "port": "COM3",
  "baudrate": 115200,
  "enable_responder": true,
  "fail_fast": true,
  "responders": [
    { "match": {"afn": 0x11}, "reply": {"afn": 0x00, "userdata_builder": "confirm"} }
  ],
  "steps": [
    {
      "name": "模拟集中器下发 11H-F1 添加从节点",
      "send": {
        "afn": 0x11,
        "seq": 1,
        "rtsa": "070919051620",
        "msaa": 1,
        "pw": 0,
        "userdata": "00 01 68 12 34 56 78 90 12 68 91 08 00 00 00 01 00 12 34 56 78 34 16"
      },
      "expect": {"afn": 0x00},
      "expect_timeout": 5.0
    },
    {
      "name": "查询从节点数量 10H-F1，期望返回数量",
      "send": {"afn": 0x10, "rtsa": "070919051620", "userdata": "00"},
      "expect": {"afn": 0x10, "nested": true},
      "expect_timeout": 5.0
    },
    {
      "name": "期望无响应的广播帧",
      "send": {"afn": 0x14, "rtsa": "999999999999", "userdata": "00"},
      "expect_no_reply": true,
      "expect_timeout": 2.0
    }
  ]
}
```

### 4.1 send（下发帧）

| 字段 | 类型 | 说明 |
|------|------|------|
| `afn` | int/str | 应用层功能码（0x11 / "11"） |
| `seq` | int | 帧序号（0~255） |
| `rtsa` | str/bytes | 终端地址，**人读顺序**（如 `070919051620`），内部自动转线上字节序 |
| `msaa` | int | 主站地址（默认 0x01） |
| `pw` | int | 密码（默认 0） |
| `userdata` | str/bytes/list | 用户数据：hex 字符串（空格/连续均可）或字节列表；转发类 AFN 可含 DAD + 嵌套 645/698 帧 |

### 4.2 expect（期望接收帧）

| 字段 | 类型 | 说明 |
|------|------|------|
| `afn` | int | 期望 AFN |
| `nested` | bool | 期望含嵌套 645/698 帧 |
| `fields` | dict | 信封字段断言（如 `{"SEQ": 1}`） |
| `nested_fields` | list | 嵌套帧内字段断言：`[{"structure":"645","field":"(当前)正向有功总电能","eq":123456.78}]` |

### 4.3 应答规则（responders，可选）

```json
{
  "match": {"afn": 0x03},
  "reply": {
    "afn": 0x03,
    "userdata_builder": "confirm" | "deny" | "echo" | "copy_rtsa",
    "userdata": "AA BB CC"
  }
}
```

- `userdata_builder`：`confirm`（回确认）｜`deny`（回否认）｜`echo`（回显上行用户数据）｜`copy_rtsa`。
- 也支持直接给 `userdata`（hex 字符串）构造任意应答载荷。
- 任务级 `responders` 覆盖内置规则；步骤级 `responders` 仅对该步生效。

## 五、结论 JSON（返回给 AI）

```json
{
  "task_id": "verify.add_node",
  "port": "COM3",
  "baudrate": 115200,
  "steps": [
    {
      "index": 0,
      "name": "模拟集中器下发 11H-F1 添加从节点",
      "sent_hex": "68 11 00 68 11 01 20 16 05 19 09 07 ...",
      "matched": "68 0F 00 68 00 01 ...",
      "parsed": { "structure": "1376.2", "fields": {...}, "nested": [...] },
      "result": "pass",
      "reason": "匹配成功"
    }
  ],
  "summary": { "total": 2, "pass": 2, "fail": 0, "verdict": "pass" }
}
```

- `steps[].parsed`：`frame_codec.decode_frame` 结构化输出——信封字段 `fields`（AFN/SEQ/RTUA/MSAA/PW/CS）+ 数据项 `items` + 嵌套帧 `nested`（645/698 的字段与数据项）。
- `summary.verdict`：全部通过为 `pass`，任一失败为 `fail`（`fail_fast` 控制是否提前中止）。

## 六、AI 烧录验证闭环示例

1. AI 完成代码烧录后，按待验证方法生成任务 JSON（参考第四节）。
2. 调用：
   - REST：`POST /api/simcon/verify`（body=任务 JSON）→ 得到结论 JSON。
   - 或 CLI：`python -m sim_concentrator verify task.json --json` → 得到结论 JSON。
3. 依据 `summary.verdict` 与每步 `reason` 判定烧录是否通过。

## 七、与 loghooks 第三来源的关系

`loghooks/sources.py` 中 `parse_concentrator_10376` 原为占位（返回 None），现已实现：
把模拟集中器下发的 13762 帧 hex 行解析为 `ParsedLine`（`fields` 为 `decode_frame` 结构化输出，
`source="concentrator_10376"`）。loghooks 引擎可把它作为第三种来源参与跨来源关联
（集中器下发帧 ↔ CCO 模块日志 ↔ 侦听台抓包，见 `docs/loghooks-design.md` 第 6.5 节）。

## 八、边界与限制

- **不依赖 GW-CASS**：帧格式统一走 `adapter_10376`（Q/GDW 10376.2 信封），不混用 GW-CASS
  `BasicFeature` 的 DL/T 1376.2 结构（见 ADR-10）。
- **不侵入 listener 采集**：独立串口通道，与侦听台只读监听互不干扰。
- **应答规则表可扩展**：内置表覆盖 00/01/02/03/10 等常用 AFN，业务新增 AFN 时在
  `responder._BUILTIN_RULES` 追加即可。
- **真实串口验证需硬件**：`serial_io` 依赖 pyserial 独占打开真实 COM；单元测试用假串口注入，
  不依赖硬件。
