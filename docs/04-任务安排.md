## 1. 状态口径

- `已完成`：验收出口有可复现证据。

## 3. 任务明细

### 任务 1：冻结验证契约

- 范围：CasePackage、Run、Evidence、AssertionResult、Report、Artifact、SourceAdapter、资源租约。
- 当前：**已完成**（2026-08-17）。领域模型在 `libs/test_automation/models.py`；新增 `fingerprint.py`（不可变指纹）、`state_machine.py`（Run 状态机，终态不可回退）、`adapters.py`（SourceAdapter）、`evidence_store.py`（证据追加/冻结）、`resource_lease.py`（资源互斥）；`models.py` 补 `Report.from_dict`。
- 阻塞：无。
- 验收出口：模型序列化、状态迁移、用例指纹、证据追加/冻结、资源互斥均有自动化测试。
- 证据：`pytest libs/test_automation` = **51 passed**（test_models_serialization / test_state_machine / test_fingerprint / test_evidence_store / test_resource_lease / test_adapters）。

### 任务 2：打通最小证据闭环

- 范围：首个安徽分钟采集用例、证据窗口、结构化断言、报告归档、基础 API。
- 当前：**已完成**（2026-08-17）。真机验证 4 块全绿（COM23 烧录成功、COM24 交互 7/8、698 主动上报 06H-F230 4/4、重复一致性）；分钟采集断言报告已用 `analyze_minute_logs.py` 对 H_LOG 产出（`docs/_evidence/2026-08-04-minute-collect-analysis.txt`，任务1 8/8/9/9 表上报成功、任务3 表000000000008 无数据失败）；断言能力已移植进 `libs/minute_assert/`。
- 阻塞：E2/E3/E4 部分协议知识点待确认，首版只使用已确认字段并显式标记未知项。
- 验收出口：固定输入结果一致；缺失来源为 `inconclusive`；报告可追到原始帧/日志。
- 证据：真机验证记录见《07》§3.1；分钟采集断言报告 `docs/_evidence/2026-08-04-minute-collect-analysis.txt`；`pytest libs/minute_assert` = 22 passed。

### 任务 3：接入三源与迁移资产

- 范围：侦听台帧、loghooks 事件、模拟集中器步骤接入；GW-CASS 用例语义与资产迁移。
- 当前：**进行中（2026-08-17）**。已完成：① `libs/minute_assert/`（分钟采集日志断言）；② **GW-CASS 用例迁移**（`libs/gw_cass_migrate/`，97 用例→CasePackage，302 断言）；③ **三源 Evidence 适配**（`libs/test_automation/sources.py`：ListenerFrameAdapter 帧→Evidence、SimConcentratorAdapter 步骤→Evidence、LoghooksEventAdapter 事件→Evidence）；④ **Run 级三源编排**（`apps/workbench/orchestration/evidence.py` + `RunExecutor` 接入：monitor 事件/stimulus 步骤/listener 帧 → 同一 run 级 EvidenceStore，串口资源租约 + Report `evidence_index`/`evidence_frozen`/`sources.listener`）。剩余：loghooks 既有引擎 Evidence 化（适配器包装已满足三源 Run，引擎本体改造延后）。
- 阻塞：真实串口和设备测试需要 Windows 硬件环境。
- 验收出口：~~一个 Run 同时消费三源证据~~ → ✅ 已达成（`collect_three_source_evidence` + RunExecutor 端到端测试）；✅ 资源冲突可预测（`acquire_serial_lease` 独占冲突 / shared 共存）；⏳ 迁移用例与旧工具结果一致（既有验证项）。
- 证据：`pytest libs/gw_cass_migrate` = 10 passed；`pytest libs/test_automation` = 58 passed（含三源适配 7）；`pytest apps/workbench/orchestration/test_evidence.py` = 11 passed（三源 Run 编排）；`pytest libs/test_automation libs/sim_concentrator apps/workbench` = 150 passed 无回归；迁移产物 `docs/_evidence/gw_cass_migrated_cases.json`。

### 任务 4：完善统一工作台与交付

- 范围：验证 UI、运行恢复、证据下钻、错误降级、一键启动和打包。
- 当前：`apps/workbench` 正在开发，listener/module_log 已有独立入口；统一交付仍需系统验收。
  - ✅（2026-08-17，WSL 内）**Run 接入 COM4 侦听台串口三源闭环**：`evidence.load_listener_frames_from_index()` 从 listener 帧索引库（`apps/listener/runtime/log_index.sqlite3`，COM4 采集落库）读帧注入三源 Run，未注入 `listener_frames` 时自动读取；库缺失优雅降级不阻断 Run。`pytest apps/workbench/orchestration/test_evidence.py` = **17 passed**；`libs/test_automation libs/sim_concentrator apps/workbench` = **156 passed** 无回归。

- 阻塞：打包依赖 .NET DLL、静态资源及 Windows 环境联合验证。
