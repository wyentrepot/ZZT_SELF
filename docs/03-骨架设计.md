# 侦听台改造项目骨架设计

> 本文只定义模块职责、输入输出、交互协议、目录和核心数据模型。需求依据见[总需求](02-总需求.md)，进度见[任务安排](04-任务安排.md)。

## 1. 分层与目录

```text
apps/
├── listener/                 # 侦听采集与报文分析
├── module_log/               # 模块日志与烧录
└── workbench/                # 统一入口与自动验证 API/UI
libs/
├── shared/                   # 基础设施及 .NET 解析桥接
├── parser_lib/               # 独立协议解析库
├── loghooks/                 # 配置驱动的日志事件引擎
├── sim_concentrator/         # 1376.2 模拟集中器
└── test_automation/          # 目标：无 UI 的验证编排内核
data/
├── logs/
└── runs/<run_id>/
```

依赖方向为 `apps → libs`；验证内核只依赖各模块公开适配器和领域模型，不导入 Web 页面或桌面壳。

## 2. 模块契约

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| listener | 文件/串口采集、索引、解析、业务分析 | 路径、串口配置、原始帧、查询条件 | 帧证据、分页与分析结果 |
| module_log | 串口日志、状态与 XMODEM 烧录 | 串口配置、固件、控制命令 | 日志、烧录进度、资源状态 |
| parser_lib/shared | 校验、协议选择、DLL/Python 解析适配 | 原始字节、协议提示 | 统一解析结果或结构化错误 |
| loghooks | 规则校验与日志事件识别 | 日志流、规则集 | 事件证据、规则诊断 |
| sim_concentrator | 1376.2 通信和步骤流程 | 端口、设备上下文、流程计划 | 步骤证据、响应或错误 |
| test_automation | 用例、资源、Run、断言、报告 | 用例包、适配器、参数 | Evidence、AssertionResult、Report |
| workbench | API 聚合、操作入口与展示 | HTTP/UI 操作 | 状态、证据下钻、报告下载 |

## 3. 核心数据模型

本节定义 `libs/test_automation` 的规范领域模型，是新用例、持久化和外部复用的目标契约。当前 `apps/workbench/orchestration` 仍保留早期交付形成的兼容投影（例如 `pending` 初态、`sources/flow_compare/feedback` 报告视图）；兼容投影不得反向改变规范模型，尚未对齐项列入[任务安排](04-任务安排.md)。

```text
Run {
  id, case_id, case_version, case_fingerprint,
  status: created|queued|running|cancelling|cancelled|passed|failed|inconclusive|error,
  created_at, started_at, finished_at, parameters, resource_leases, error
}

Evidence {
  id, run_id, kind: frame|event|interaction|measurement|log,
  source, observed_at, sequence, correlation_key,
  payload, raw_ref, metadata
}

AssertionResult {
  id, run_id, assertion_id,
  outcome: pass|fail|inconclusive,
  expected, actual, evidence_ids, message
}

Report { run_id, summary, steps, assertions, evidence_index, artifacts }
Artifact { id, run_id, type, path, sha256, created_at }
```

Run 终态不可回退，测试不满足与系统错误分离。Evidence 追加写入，`raw_ref` 指向不可变原始内容或摘要。Report 是派生结果，Evidence 与 Artifact 清单是审计基础。

## 4. 用例与执行流程

用例包包含清单、参数、资源要求、步骤、断言和版本信息；加载时计算不可变指纹。

```text
发现并校验用例 → 创建 Run → 获取资源租约 → 启动适配器
→ 执行步骤并收集 Evidence → 冻结证据窗口 → 执行断言
→ 生成 Report/Artifact → 释放资源
```

取消先进入 `cancelling`，适配器幂等清理后进入 `cancelled`。清理失败写入错误，但不得删除已有证据。

## 5. 适配器协议

```python
class SourceAdapter:
    def start(self, run_context): ...
    def collect(self, evidence_sink): ...
    def stop(self): ...
    def health(self): ...
```

实现可同步、异步或使用后台线程，但 `stop()` 必须幂等，源错误必须转换为统一错误类型。硬件端口由资源租约独占，离线文件可共享只读。

## 6. API 骨架

### 6.1 当前已实现兼容接口

| 方法与路径 | 用途 |
|---|---|
| `GET /api/scenarios` | 列出场景模板 |
| `POST /api/run` | 创建并异步启动 Run |
| `GET /api/run/{id}` | 查询 Run 状态 |
| `POST /api/run/{id}/cancel` | 请求取消 |
| `GET /api/run/{id}/report` | 获取报告及内嵌证据下钻数据 |
| `GET /api/runs` | 列出历史 Run |

以上路径是已交付兼容接口，不应直接改名。规范化 API 可在保持兼容别名的前提下演进。

### 6.2 尚未闭环的接口契约

- Evidence 当前随 Report 内嵌返回，尚无独立分页接口。
- Artifact 尚无登记、校验和下载接口。
- FastAPI 默认 `detail` 错误尚未统一为 `code`、`message`、`details`、`request_id`。
- 所有接口均不得泄漏线程对象、串口句柄或本机绝对路径。

## 7. 持久化、并发与界面

- 元数据可存 SQLite；Evidence 使用追加式 JSONL 或等价顺序存储。
- 同一 Run 的 `sequence` 单调递增；写入立即刷新，冻结后拒绝追加。
- RunStore 原子校验状态迁移；资源租约以资源类型和稳定标识为键。
- 大文件通过索引和分页访问；原始数据与派生数据分目录保存。
- 工作台用页签组合功能，核心状态来自 API 和持久化，浏览器内存不作为权威状态。

## 8. 子系统状态机

| 对象 | 合法主路径 | 异常/恢复约束 |
|---|---|---|
| listener 日志索引 | `idle → queued → indexing → completed` | 失败进入 `failed`；重新导入可重建索引，原日志不变 |
| module_log 串口会话 | `idle → running → idle` | 打开异常抛出并保持原状态；读取异常进入 `error`；同一通道运行时重复启动返回现有状态 |
| XMODEM 烧录 | `starting → transfer → done/error` | `flashing` 表示占用中；`done` 明确成功，`error` 携带失败原因；最终清理响应队列 |
| sim_concentrator 端口 | `closed → opening → open → closing → closed` | 流程任务只能绑定 `open` 端口 |
| sim_concentrator 单次任务 | 同步执行，结果由 `summary.verdict=pass/fail` 表达 | 每一步保留请求、响应与判定；当前不提供异步取消和任务级持久状态 |

子系统状态通过适配器映射到 Run，不把底层状态直接当作 Run 终态。完整转换规则应由相应模块测试锁定。

## 9. 实体关系与接口全局约定

- CasePackage 以 `case_id + version + fingerprint` 唯一确定，可产生多个 Run。
- Run 拥有 Evidence、AssertionResult 和 Artifact；Report 对它们做只读汇总。
- Evidence 可被多个 AssertionResult 引用，但不得在断言后改写。
- 所有时间使用带时区 ISO 8601；ID 为稳定字符串；列表接口必须分页。
- 写接口支持请求关联标识；重复取消与停止操作必须幂等。
- 对外路径使用逻辑 Artifact ID，服务端负责解析真实路径并防止目录穿越。
- API 兼容性变更必须显式版本化；当前历史 OpenAPI/Schema 快照仅供归档参考。

## 10. 设计约束

协议字段以[`_references/protocols/`](_references/protocols/)为唯一外部依据。更细实现讨论保留在历史归档，不继续作为现行契约。本文件变更须经过设计评审。

## 11. 保留扩展：Windows 串口网关

Windows 串口网关对应总需求 CR-1，当前已屏蔽且不属于现行骨架。仓库不得依赖尚不存在的 `serial_transport.py` 或 `windows_uart_bridge.py`。历史 schema、状态机和验收设想保留在[专项方案](_archive/2026-08-18/05-Windows串口转TCP与WSL虚拟串口方案.md)，恢复需求后须重新评审方可写回本骨架。
