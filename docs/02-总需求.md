# 侦听台改造项目总需求

> 本文只定义范围、功能需求、非功能需求和验收标准。架构实现见[骨架设计](03-骨架设计.md)，完成状态见[任务安排](04-任务安排.md)。

## 1. 用户与范围

主要用户为协议研发、固件研发、测试及现场问题分析人员。系统覆盖离线日志定位、实时侦听、模块维护与烧录、场景自动验证、修复后回归五类任务。

## 2. 功能需求

### FR-1 侦听与报文分析

- 支持日志文件导入、流式索引、分页浏览、筛选和来源定位。
- 支持串口实时采集，原始数据先可靠落盘再进入分析链路。
- 支持国网、南网 HPLC 帧及相关业务协议解析，并保留原始帧。
- 支持大文件和分钟采集等业务分析。
- 实时采集与离线分析的资源冲突必须显式处理。

### FR-2 模块日志与烧录

- 支持 CCO/STA 串口日志实时采集、时间戳、分类落盘和查看。
- 支持 XMODEM 固件烧录，并反馈进度、成功或失败原因。
- 烧录与日志采集共享串口时必须有明确的资源状态和恢复行为。

### FR-3 日志事件监控

- 以配置化规则从模块日志识别关键事件和运行阶段。
- 事件包含来源、时间、规则标识、原文或原文引用。
- 支持规则校验、启停和版本追踪；错误规则不得影响原始日志采集。

### FR-4 模拟集中器

- 支持 1376.2 报文收发、校验、序列管理和超时处理。
- 支持声明式步骤组织交互流程，记录每一步输入、输出和判定。
- 支持端口管理、设备上下文和可重复执行的验证任务。

### FR-5 自动验证闭环

- 支持发现、校验和加载版本化测试用例包。
- 支持创建、启动、取消和查询 Run，并协调串口等独占资源。
- 将帧、日志事件、交互步骤统一封装为 Evidence。
- 支持帧字段、事件出现/不出现、STA 清单覆盖、跨来源聚合等结构化断言。
- 证据不足产生 `inconclusive`，不得伪装为 `pass` 或 `fail`。
- 生成可归档 Report 和 Artifact，结论可下钻到证据与原始来源。
- 支持迁移 GW-CASS 中仍有效的用例语义和测试资产。

### FR-6 统一工作台

- 单一入口提供验证工作台、模块日志、侦听分析等功能页。
- 页面通过稳定 API 使用能力，核心编排不得依赖 UI。
- 展示运行状态、步骤、断言、证据和报告，并支持取消和错误恢复。
- 某一硬件或 DLL 不可用时，其余功能可降级运行。

### FR-7 共享协议与基础设施

- 共享解析库提供统一输入校验、协议选择、结构化输出和错误模型。
- 协议字段以[`_references/protocols/`](_references/protocols/)中的原文为准。
- API、数据库及文件格式必须有版本或兼容策略。

### FR-8 工程化与交付

- 支持 Windows 硬件运行与 WSL/通用环境中的纯逻辑开发测试。
- 提供自动化测试、依赖锁定、日志、配置和一键启动/打包能力。
- 发布物不得依赖开发机绝对路径，运行数据不得污染源码目录。

## 3. 非功能需求

- NFR-1 可追溯性：报告、断言和证据有稳定 ID，可追到原始输入和用例版本。
- NFR-2 可靠性：采集数据优先落盘；异常退出后已完成证据不丢失。
- NFR-3 性能：大文件采用流式或索引方式，界面不因全量加载阻塞。
- NFR-4 可测试性：协议解析、规则、流程和断言可在无真实硬件条件下单测。
- NFR-5 可维护性：模块边界明确，同一事实和字段只在一个契约中定义。
- NFR-6 安全性：文件路径、上传内容、串口参数和外部进程输入必须校验。
- NFR-7 可观测性：Run 和关键资源状态有结构化日志及明确错误码。
- NFR-8 兼容性：目标运行环境为 Windows；纯 Python 逻辑支持 CI/WSL 验证。

## 4. 系统级验收标准

1. 能从真实或固定样例用例创建 Run，接入至少两种证据来源并生成可下钻报告。
2. 同一固定输入重复运行得到相同断言结果和可比对的证据清单。
3. 缺少必要来源时为 `inconclusive`；存在明确不匹配时为 `fail`。
4. 大日志导入和分页浏览不要求将文件一次性载入内存。
5. listener、module_log、loghooks、sim_concentrator 与编排内核均有独立测试入口。
6. DLL 或串口缺失时给出明确降级信息，不阻断无关页面。
7. Windows 发布包可在干净目标目录启动，静态资源、规则和依赖完整。

## 5. 范围控制

新增需求必须先获得唯一 FR/NFR 编号和验收出口；实现进度不得写入本文件。本文件变更须经过需求与设计评审。
