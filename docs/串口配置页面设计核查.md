## 2. 设计初衷（三层递进）

### 2.1 第一层：REQS-0004 定义的根本问题（2026-08-20）

`reqs/0004-workbench-serial-sessions/REQS.md` §1 列出 5 个待解痛点：

1. 工作台切页会销毁 iframe，串口连接与页面状态丢失；
2. 后端串口可能仍被占用，页面却显示未启动，再点启动报「端口被占用」；
3. **设备名 ↔ Windows COM 号的映射只存在于 `apps/listener/serial_com_map.json`**，模块日志没复用，改映射要改代码；
4. 模块日志固定 CCO/STA 双通道，无法按需扩展；
5. 日志缺少稳定串口身份，同角色多串口不易辨认来源。

对应目标（§2.1）中，与本页直接相关的是：
- **建立外部 JSON 统一串口映射**（`config/serial_ports.json`），侦听台与模块日志共用，以后换串口只改 JSON 不改代码；
- 映射能描述 **Linux/WSL 设备名、Windows COM 号、显示名称、默认用途、模块类型**；
- 每会话独立保存 **串口参数、连接状态、日志缓冲、发送、烧录状态**。

> 一句话：**初衷不是「做一个配置表单」，而是消灭「改串口要动代码」这件事。**

### 2.2 第二层：REQS-0005 的 P3/P4/P6 落地为 ADR-32/33/35（2026-08-23）

| ADR | 决策 | 设计意图 |
|-----|------|----------|
| **ADR-32**<br>P3 Profile Store | 固定四槽 `module_log.cco` / `module_log.sta` / `listener.main` / `simcon.main`，**默认 `enabled:false`**；原子写入 `data/runtime/serial_profile.json`；选 mapping_id 时**从 `serial_ports.json` 回填默认波特率/数据位/校验/停止** | 一份**可保存、可校验、且不破坏现场映射**的 Profile 存储。`serial_ports.json` 只读不被改 |
| **ADR-33**<br>P4 一键应用 | `SerialProfileApplier` **固定顺序 侦听台→CCO→STA→模拟集中器**；逐槽状态 `started/reused/stopped/unchanged/skipped/failed`；**单槽失败继续执行，不回滚成功项**；只停 `托管-` 前缀会话，**不影响人工动态会话** | 把已保存 Profile **一次性落到真实串口服务**，逐槽可观测、部分失败可继续、人机互不干扰 |
| **ADR-35**<br>P6 配置页 | 原生静态配置页，固定四槽；**保存 / 一键应用 / 刷新状态三动作各自独立**；每槽含 启用、映射下拉、波特率/校验、**状态/占用**、应用结果；启用未选串口→内联报错；重复映射零副作用 | 给 P4 一键应用配一个**可视化操作页**，让用户能在浏览器里完成四槽配置与应用 |

### 2.3 第三层：服务对象是人 + AI 共享（REQS-0004 §20）

这是最容易被忽略、但最关键的一层初衷：

> **串口独占发生在「后端会话 ↔ 物理串口」之间，不发生在人和 AI 之间。**

```
物理串口 <--唯一 pyserial 句柄-- 后端串口会话
                                    |-- UI 读取状态/日志
                                    |-- AI 读取状态/日志
                                    |-- 服务端观察任务匹配规则
```

UI 和 AI 都是同一后端服务的客户端，不直接开串口。四槽 apply 的深层价值是：**AI 能用一个动作让全部硬件进入就绪态**，而不必理解三个子应用的内部接口。

## 4. 漂移与缺陷（本次核查发现）

### 🔴 缺陷 1【实锤 Bug】状态 / 占用 是永远不更新的死字段

`serial-profile.js:180-184`：

```js
status.innerHTML =
  "<dl>" +
  "<dt>状态</dt><dd id='st-" + def.slot + "'>…</dd>" +
  "<dt>占用</dt><dd id='own-" + def.slot + "'>…</dd>" +
  "</dl>";
```

**全文件检索 `st-` / `own-`，除这两行外再无任何引用** —— 两个字段渲染出 `…` 后再无人赋值，永远停留在 `…`。

对照：
- **ADR-35** 白纸黑字要求每槽含「状态/占用/应用结果」；
- **真机验收清单 §2 第 3 条**写着 `[x] 刷新状态（GET）：应用后各槽 status/占用/应用结果 反映真实串口状态`。

→ **该验收项实际不成立**。真实更新的是「应用结果」（`.result`），「状态/占用」被顺带打了勾。

**影响**：用户点完「一键应用」后，看不到各槽串口当前是 running / idle / error，也看不到被谁占用——而这两项恰恰是 ADR-33「逐槽可观测」的核心诉求。

**✅ 2026-09-05 已修复**：

| 层 | 改动 |
|----|------|
| `serial_profile_applier.py` | 新增 `snapshot()`：复用已有 `_current_state()`，按 `PROFILE_SLOTS` 顺序返回四槽 `{state, owner}`，**只读，不打开/关闭任何串口** |
| `serial_profile_api.py` | 新增 `GET /api/serial-profile/status`；applier 未配置时返回 **503** 而非伪装全空闲。**未改动 ADR-33 的 GET/PUT/apply 三接口契约** |
| `serial-profile.js` | 新增 `loadStates()`；`renderSlots()` 回填 `st-*` / `own-*`；状态枚举中文化（`running→运行中` 等） |
| 触发时机 | `init()` / `doRefresh()` / `doApply()` 均调用 → 「刷新状态」名副其实，apply 后立即反映真实状态 |

**连带修复（原核查未列出）**：`renderSlots()` 重建卡片时会把刚填好的「应用结果」一并清空——原代码只创建空 `div.result`，从不回填 `applyResult`。现已从 `applyResult` 回填并带上 `ok/fail` 样式。

### 🟠 缺陷 2「刷新状态」按钮名不副实

`doRefresh()`（`serial-profile.js:316-328`）只做两件事：`loadProfiles()` + `loadPorts()` 然后 `renderSlots()`。

**它不读取任何串口运行状态**，因此刷新后「状态/占用」依然是 `…`。按钮语义与实现不符。

**✅ 2026-09-05 已修复**：`doRefresh()` 改为
`Promise.all([loadProfiles(), loadPorts(), loadTags(), loadStates()])` —— 角色标签与各槽实时状态一并刷新，按钮语义与实现一致。

### 🟡 缺陷 3 数据位 / 停止位在 UI 上完全不可配

- 后端 `PUT /api/serial-profile` 明确接受 `bytesize` / `stopbits`（`serial_profile_api.py:84-85`）；
- 但前端 `collectProfiles()` 只提交 `mapping_id / enabled / baudrate / parity` **四项**，页面也**没有**数据位/停止位的输入控件。

对照 **REQS-0004 §4.4** 要求 `serial_config：波特率、数据位、校验位、停止位` —— 缺 2 项。

→ 实际只能吃 `serial_ports.json` 的回填默认值。**换了一台非标串口参数的设备，UI 上改不了。**

### 🟢 附注：P6b 是范围外的增量

「串口角色标签」区块（角色↔COM 绑定）不在 ADR-35 原始设计内，是后续追加能力，已实现且不影响主线判定。

### 端口与运行态核查

- 8790 工作台当前**未在运行**（`curl http://127.0.0.1:8790/...` 返回 `Connection refused`）。
- 用户确认截图来自 8790 工作台 → 截图必然是**该服务**在某个时刻渲染的。

### 推论

仓库代码本身从未产生过这些文案，git 历史所有分支也不存在。这意味着 8790 服务进程加载的 HTML/JS **不是**仓库里的 `serial-profile.html/js`——要么来自某个**未受版本控制的临时副本**，要么被**页面渲染链路上的中间层**改写了。

最可能的两种解释（按可能性排序）：

1. **某个 AI 编码工具/浏览器扩展接管了渲染**。例如 CodeBuddy / opencode / WorkBuddy 的 live preview，或者 Chrome/Edge 的翻译插件。其中：
   - 「**（粘贴）**」是决定性线索——「粘贴」是 "paste" 的直译，而正确中文应是「已固定/已绑定」（英文 "pinned" 一词多义被误译）；
   - 「**（中）**」很像 "(in progress)" 或 "(medium)" 的翻译残留；
   - 「**模块基类默认**」「**硬件名称项目**」「**模拟体卡项类项目**」呈同一翻译模式——把技术标识（`module_log.cco` 等）直译为自然中文短语。
2. **8790 服务进程是从某个临时副本启动的**（如把仓库外的某个 HTML 直接放在 static 目录），且未受版本控制；服务停止后副本消失，`grep -rl` 自然找不到。

无论哪种，**与仓库代码无关**：P6 四槽 Profile 页（`serial-profile.html/js`）的实际渲染效果以仓库代码为准，不是截图所示。

## 6. 修复建议（按优先级）

| 优先级 | 事项 | 说明 |
|--------|------|------|
| P0 | 补齐「状态/占用」的取数逻辑 | 需后端在 `GET /api/serial-profile` 或新增状态接口里，返回各槽对应托管会话的 `state` 与占用者，前端回填 `st-*` / `own-*` |
| P1 | 让「刷新状态」名副其实 | 刷新时一并拉取各槽实时状态，而非只重载 Profile 与端口列表 |
| P2 | 补数据位 / 停止位控件 | 前端加两个 select，并在 `collectProfiles()` 提交 `bytesize` / `stopbits` |
| P3 | 修正真机验收清单 §2 第 3 条记录 | 该勾不成立，建议标注为「部分成立：仅应用结果字段反映真实状态」 |
