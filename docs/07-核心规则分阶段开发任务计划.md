> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **当前状态：⛔ 暂不执行（仅完成计划）**
>
> **启动条件：** 只有用户明确下达“开始执行计划”或指定某个阶段开始后，才允许修改代码、执行开发测试或提交 Git。

**Goal:** 在保持模块日志、侦听台和模拟集中器三源独立的前提下，建立“事实识别 → 成功契约 → 确定性判定 → 最小证据包 → AI 反馈”闭环。

**Architecture:** 三源只产生标准化 Detection Event/Evidence，不直接相互调用。独立 `VerificationEngine` 对冻结证据执行版本化 `VerificationCase`，得到 `pass/fail/inconclusive/error`；报告层输出 L1 AI 摘要、L2 失败证据包和 L3 原始证据引用。实时验证和历史回放共用同一引擎，最终结论只由冻结证据产生。

**Tech Stack:** Python 3、Pydantic、SQLite、FastAPI、pytest、现有 `libs/test_automation`、`libs/loghooks`、`libs/sim_concentrator` 和 `apps/workbench`。

## Global Constraints

- 本计划当前只供评审，不执行任何开发任务。
- 侦听台是网络层帧事实源；模块日志是模块调试口打印事实源；模拟集中器是 13762 交互刺激源。
- EventStore/EventBus 只记录事实，不执行成功判定。
- 日志默认是诊断证据，不是所有流程的必需成功条件；用例可显式将日志步骤声明为 required。
- `VerificationCase` 第一版使用 JSON，未知字段拒绝加载，每次 Run 冻结原文、版本和 SHA-256。
- 相关键优先于时间匹配；多候选且无法唯一确定时返回 `inconclusive`。
- 流程时限使用单调时间计算，墙上时间只用于展示、导航和原始数据关联。
- 最终结论为 `pass | fail | inconclusive | error`，不得把采集缺口、解析失败或来源不可用判成业务失败。
- L1 AI 摘要目标 1–3 KB；L2 单失败步骤上限 16 KB 或 50 条证据，先达者为准；L3 只按引用读取原始数据。
- 原始日志和侦听数据保持路径引用，同时记录 size、mtime 和 SHA-256；引用失效时历史结论可查，重新验证返回 `inconclusive`。
- 不在本计划内实现 AI 自动改代码、自动提交、编译系统重构、烧录系统重构、13762 协议大规模补全、图形化规则编辑器和多用户权限。
- 首个端到端用例只覆盖“分钟采集配置 → 配置应答 → `result=0` → 主动上报 → `06H-F230` 关键字段”。
- 每个阶段完成后必须停止，提交测试证据并等待用户确认，不得自动进入下一阶段。

```python
class VerificationOutcome(str, Enum):
    PASS = "pass"
    FAIL = "fail"
    INCONCLUSIVE = "inconclusive"
    ERROR = "error"


class EventExpectation(BaseModel):
    model_config = ConfigDict(extra="forbid")
    source: str
    event_type: str
    fields: dict[str, Any] = Field(default_factory=dict)


class VerificationStep(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: str = Field(min_length=1)
    after: str | None = None
    within_ms: int | None = Field(default=None, gt=0)
    required: bool = True
    negate: bool = False
    expect: EventExpectation


class CorrelationSpec(BaseModel):
    model_config = ConfigDict(extra="forbid")
    keys: list[str] = Field(min_length=1)


class VerificationCase(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: str = Field(min_length=1)
    version: str = Field(min_length=1)
    name: str = ""
    trigger: EventExpectation
    correlation: CorrelationSpec
    steps: list[VerificationStep] = Field(min_length=1)
```
