# `meter.read_645` — 抄读表数据（02H-F1 透传 645 11H，只观测，不判定）

> 版本 **v0.1（待审）** ｜ 所属层：原子块 ｜ 领域：抄表（STA 透传 645）
> 一句话：**把一帧 645 读数据（11H）透传给一只表，如实返回"收到没有、帧里是什么、数解出多少"；不判断这些数算不算通过。**

---

## 0. 本版说明（首版，立三条口径）

| 项 | 本版立场 |
|---|---|
| 判定权 | 块只报观测；"抄到的数对不对"由用例判（**默认只验"有值且可解"，不校验数值真值**，0044 §8.1-4） |
| 块级结论 | 只有"拿到观测"或"没拿到 + 原因"，**没有"说不清"这种块级结论** |
| 观测完整性 | 走到哪一层报哪一层；不完整也要如实报（等了多久、重发几次、最后一次为什么） |

**为什么这么定**：同一只表，在"日常抄表"用例里期望读到一项可解的数，在"表未入网"的负例里期望**根本读不到**。判据写在块里，这两种期望就得造两个块——块失去复用，判据也会漂（与 `archive.add` v0.2 同一条口径）。

---

## 1. 一句话职责

**透传一次 645 读数据，返回这一帧读数据的观测。**

- 它回答：*"表回帧了吗？回的内层 645 帧合法吗？DI 是我要的那一项吗？数解出来是多少？"*
- 它**不**回答：*"这个数对不对？"*（调用方拿期望值比对）
- 它**不**回答：*"这只表在不在网 / 档案里有没有？"*（组网块、档案块的事）

---

## 2. 做什么（执行路径）

```
调用方给出：表地址 + 数据标识 DI（可选：期望数值、等待预算）
        │
        ▼
 ① 构 645 11H 读数据帧（地址域 = 表地址线序；DI 显示序→传输序逐字节 +33H）
        │
        ▼
 ② 等待预算 > 0 ？
        ├─ 是 → 只读闸门：控制码必须 11H/13H，否则拒跑（零下发）
        │        每 5 秒重发**同一帧**，直到拿到合格观测或用尽预算
        └─ 否 → 只发一次
        │
        ▼
 ③ 收到上行 02H-F1 了吗？
        ├─ 没有 ──→ 观测【无应答：等了多久 / 重发几次 / 最后一次原因】
        ▼ 收到
 ④ 能按 1376.2 解开吗？ 解不开 → 观测【收到帧但解不开（附解析器原因）】
        ▼ 能
 ⑤ 外层协议类型=645-2007 且带「转发报文」吗？
        否 → 观测【回的不是 645 转发 / 02H-F1 里没有内层 645】
        ▼ 是
 ⑥ 内层能按 645 解析吗？ 不能 → 观测【内层帧不可解（附原因 + 帧原文）】
        ▼ 能
 ⑦ CS 合法吗？ 不合法 → 观测【CS 不合法，**不解读数值**】
        ▼ 合法
 ⑧ 控制码 D6=1（从站异常应答）吗？ 是 → 观测【从站异常应答，无数据】
        ▼ 正常应答
 ⑨ DI 回显吗？ 不回显 → 观测【DI 回显不符（期望字节 vs 实际帧原文）】
        ▼ 回显
 ⑩ 数值可解吗？ 不可解 → 观测【数据域未解出数值】
        ▼ 可解
 ⑪ 观测【DI / 数据项名 / 数值 / 单位 / CS 合法 / 回显一致（+ 与期望值的比对）】
```

**图上没有"通过 / 失败"** —— 因为这两件事不归块管。每一层都是独立观测：走到第几层就报到第几层。

## 3. 返回什么（观测清单）

| 层 | 观测项 | 取值 |
|---|---|---|
| 有无 | 是否收到上行帧 | 收到 1 帧 / 一帧都没收到（+ 等了 N 秒、探测 K 次、单次最多等 S 秒） |
| 留痕 | 上行帧原文 | 帧 hex（收到才有） |
| 外层 | 通信协议类型 | 0x02 符合期望 / 其它值 / 未给协议则不自证 |
| 内层 | 是否有内层 645 | 有转发报文 / 没有该字段 / 内层不可解（附解析器原因） |
| 内层 | CS | 合法 / 不合法（附原文）/ 未走到这一步 |
| 内层 | 控制码 | 正常读数据应答 / 从站异常应答（D6=1）/ 其它 |
| 内层 | DI 回显 | 回显一致 / 不一致（期望回显字节 + 实际帧原文）/ 未走到这一步 |
| 内层 | 数值 | 解出（数据项名 + 数值 + 单位）/ 未解出（数据项全空） |
| 比对 | 与期望值 | **默认不比**；调用方显式给期望值时才比（一致 / 不一致） |

**"收到帧"不等于"抄到了"** —— 这是本块最容易被误读的地方，四种情形观测完全不同：

| 情形 | 观测长什么样 | 说明了什么 |
|---|---|---|
| DI 回显不符 | 收到帧、CS 合法，但回显的不是这一项 | 链路通、表在答，只是答的**不是这一项** |
| CS 错 | 收到帧、内层按 645 解析但 CS 校验不通过 | 帧结构坏了，**数值一律不解读**（哪怕字节看着像） |
| 数值解不出 | 帧合法，数据项全空 | 帧到了，内容不是可解的数据单元 |
| 一帧都没有 | 无上行帧 + 等待读数 | **没有任何证据**说明表在答（≠ 表没数据） |

**等待读数怎么读**：预算与单次上限**不叠乘**——单次最多等待"显式上限"与"剩余预算"中较小的一段，下限 1 秒；总时长由预算兜住。所以"预算 30 秒 + 单次上限 15 秒 + 间隔 5 秒"不是"6 次 × 15 秒"：**无应答时**每次尝试会把预算整段吃掉，实际只有两三次；**有应答但数值或 DI 不符时**每次 2.3–2.6 秒就回，次数才接近"预算÷间隔"。说明里如实写"等了 N 秒共 K 次尝试"，次数以实跑为准，不预设。

**取 t 的那次查询不算在预算里**：调用方没给显式单次上限时，块才会去问 CCO 的从节点监控最大超时时间（03H-F7，查询本身 ≤6 秒，同一次运行只问一次），按 t+5 秒定单次上限；问不到就回落 60 秒。用例里显式钉了 15 秒的，**不查 t**。这也是"预算必须由调用方给"的另一面：块能算"最多等多久"，算不出"这条链路几分钟才恢复"。

## 4. 调用方怎么判（四个典型用法）

```
用法一 抄电能  期望观测：收到帧 + 内层可解 + CS 合法 + DI 回显 00010000 + 数值可解
               （**不校验数值真值**——只要解出非空数值即算观测符合）
用法二 抄电压  期望观测：DI 回显 02010100 + 数值可解（瞬时量，同样不校验真值）
用法三 负例    期望观测：一帧都没有（表未入网 / 地址错）→ 拿不到才是对的
用法四 只验链路 期望观测：收到帧 + CS 合法 + DI 回显 + 数值可解（**值不限定**）
```

**同一个块，在用法一里期望"有值"，在用法三里期望"没有值"，在用法四里还能显式给期望值做精确比对——这就是判据必须归调用方的原因。**

## 5. 参数

| 参数 | 含义 | 默认值 |
|---|---|---|
| 数据标识 DI | 645 读数据要读哪一项（显示序 8 位十六进制） | 00010000（正向有功总电能） |
| 期望数值 | 可比对的数值（电能 kWh / 电压 V） | 不给（只报解出的值） |
| 表地址 | 12 位 645 表地址，块内换成帧地址域线序（**不反序**） | 配置默认 `123456789012` |
| 通信协议 | 2 = 645-2007 / 1 = 645-1997 | 2 |
| 单次应答等待上限 | 一次透传等回帧的秒数；显式 > 按 03H-F7 取 t + 5 秒 > 回落 60 秒 | 回落 60 秒；用例里钉 **15 秒** |
| 等待预算 / 重发间隔 | 反复重发的总预算秒数（0 = 只读一次）；两次透传之间隔几秒 | 0（用例里 30 秒）/ 5 秒 |

三条纪律：

1. **一次只能给一只表**。给多个 → 报参数错，不猜先读哪只；
2. **给了但不合法 ≠ 没给**。非法表地址 / 非法等待参数一律报配置错误，绝不静默换成默认表地址或默认秒数（否则"传错地址"会变成"拿默认那只表去判"）；
3. **等待期只读**。白名单只有 11H 读数据 / 13H 读通信地址；写帧（12H 冻结、14H 写数据……）带着等待预算进来 → 直接拒跑，零下发。

## 6. 副作用与收场

| 项 | 内容 |
|---|---|
| 副作用等级 | **只读**（11H 读数据不改变表内任何状态） |
| 占用 | 透传独占工作台的模拟集中器会话与串口；等待期反复占用。409 闸门忙 / 服务不可达 → 不判设备，交上层重跑 |

## 7. 反例（怎么证明它没撒谎）

判据搬走之后，块要证明的是**观测本身的正确性，以及"没抄到"的四种情形不许混说**：

| # | 反例 | 期望观测 | 防的是 |
|---|---|---|---|
| R1 | DI 回显不符（要 00010000，回显 33343435 即 02010100） | 收到帧、CS 合法、**DI 回显不符** + 帧原文 | 把"别的数据项"当成本项抄到 |
| R2 | CS 错 | 收到帧、内层可解析但 **CS 不合法**，**不报数值** | 拿坏帧里的字节硬凑一个数 |
| R3 | 等待期一直无应答 | **一帧都没有** + 等了 N 秒共 K 次尝试 + 最后一次原因（轮询超时） | 把"没拿到观测"说成"表里没数" |
| R4 | 调用方显式给了期望值、实际解出的值不同（解出 1234.00，期望 1234.56） | CS 合法、回显一致、数值可解 = 1234.00 kWh、**与期望不符** | 把"链路通但数不对"混成"读不到"（默认不比对，此例仅在显式给期望值时有意义） |
| R5 | 收到帧但内层没有 645 / 内层解不开 | 外层收到、无转发报文 / 按 645 解不开（附原因） | 拿一帧非 645 转发充数 |
| R6 | 写帧 + 等待预算 > 0 | **拒跑**（配置错误），零下发 | 等待循环变成反复对表下发写动作 |

R1–R4 是必须项。**R3 与 R4 的差别是这份文档的重点**：R3 没拿到任何观测（说不清链路），R4 拿到了完整观测只是数不对（表在答，问题在数据）。

## 8. 明确不做什么

- **不判定通过 / 失败**（调用方的事）；
- **不判断档案里有没有这只表**（档案块的事）、**不判断入网是否达标**（组网块的事）；
- **不判断"这个数该不该是 1234.56"**：期望值由调用方给，比对结论归调用方；块只报"解出多少"；
- **不做任何写操作**，也不在等待期重发写帧；
- **不推算等待节奏**：t 只是"单次最多等多久"的参考，不是判据；链路恢复要多久，块不知道；
- **不判断链路是否稳定、不定位断在哪一跳**（两次数值不同不是本块的结论；CCO 有没有转发、表有没有收到，块只报"有没有上行帧"）。

## 9. 调用方义务（必须写进用例规范）

> **凡以"抄到了电能 / 电压"为目的的用例，必须自己给出数据标识 + 等待预算，并声明"期望数值可解"；显式给期望值时才做精确比对。只跑块不看观测的用例，视为缺判据，不得入库**（0044 §8.1-4）。

1. **必须显式给单次应答等待上限**（用例里钉 15 秒 = 实测往返 2.3–2.6 秒的 6 倍余量）。不给就会按 03H-F7 推算或回落 60 秒，白等；
2. **必须给等待预算**（日常 30 秒；复位后要放宽）。块不知道这条链路的恢复节奏，预算只能由最了解场景的一方给；
3. **必须把"没拿到观测"与"拿到但不符合"分开上报**：前者是台架 / 链路，后者是产品。

## 10. 与当前实现的差异（待改代码）

本文写的是**目标契约**。现有代码仍是旧口径，差在五处：

| 差异 | 现状 | 目标 |
|---|---|---|
| 谁来判 | 块内判 CS / DI 回显 / 数值可解，给了期望值还比数值 → 直接出 pass / fail | 块只报观测，判据搬到调用方 |
| 块级结论 | 四态：pass / fail / unknown（说不清）/ skipped（依赖不可用） | 两件事：拿到观测 / 没拿到（含原因） |
| 重试下的分流 | 等到成立→pass；等满无帧→unknown；等满有帧但判据不成立→fail | 保留"有帧 / 无帧"的区分，但**不再叫 fail / unknown**，改称观测形态 |
| 期望值比对 | 块内完成，不一致即 fail | 块返回解出的数值 + 单位，比对由调用方做 |
| 引用方 | 现有 2 条用例 4 处调用，靠块的 pass 直接得结论 | 用例必须显式写"期望数值"并自行比对 |

**改代码之前，本文档描述的契约不生效**；现有代码行为以代码为准（等待型重试、只读闸门、预算扣减、只读白名单这几项**已实现**，与目标无差异）。

## 12. 待确认（请你定四件事）

1. ~~期望值比对留在块内还是搬到调用方~~ → **已定（0044 §8.1-4）**：搬到调用方；且默认**不比对数值真值**，只验"有值且可解"。块须稳定携带"数据项名 + 数值 + 单位"。
2. **等待预算的默认值要不要给**？（现状默认 0 = 只读一次）日常 30 秒、首次入网抄表 30 秒对不对？首次入网复位后实测链路恢复要十几分钟，而绑定表那步给了 180 秒，抄表只给 30 秒——差距是有意的还是漏的，需要拍板。
3. **"拿到帧但内层没有 645 证据"算观测还是算缺陷？** 现状块判 fail（回了转发报文却不是要的内容），事实层判 unknown（没探到 ≠ 不存在）；目标态里它只是"内层不可解"这种观测——还要不要保留"这本身就是缺陷"的额外标记？
4. **R1–R6 够不够？** 还差"两次抄表数值不同（电能累计 / 电压漂移）"这类反例吗？它是观测项还是调用方的容差问题？
