# 流程：单表抄表（建档 → 组网 → 绑表 → 抄电能 → 抄电压）

> 版本 **v0.1（待审）** ｜ 类型：**流程**（不是块）｜ 领域：抄表（645 透传）
> 一句话：**按六步依次拿观测，证明"这只表能被抄到数据"；每一步只报观测，结论由本流程按"期望 vs 观测"算。**

---

## 0. 适用与前提

- **单只表**：一次只挂一只表跑；多表并发、组网规模不在本文范围；
- **台架在线**：工作台模拟集中器服务可用、STA 上电、串口不被他方占用；
- **地址口径**：默认表地址 `123456789012`（645 人读口径）；**档案地址是电表地址整体反序 = 129078563412**（同一串 6 字节 BCD 反序，换算只有一处实现，调用方不用管）；
- **日常版假定链路已在网**；首次入网版先复位（差异见 §5）；本文写的是**目标态**（判据归调用方），与现状的差别集中在 §8；四个块各自的观测定义见同目录的块文档（`archive.add` / `nwk.topology` / `meter.addr_probe` / `meter.read_645`）。

---

## 1. 这套流程证明什么、不证明什么

- **证明**：这只表**能被抄到数据**——建档命令被接受、档案落地、组网计数达标、STA 能取到本表地址、两项数据（电能与电压）读回合法帧且数值可解（**不校验数值真值**，0044 §8.1-4）；
- **不证明**：多表并发、组网规模与拓扑质量、链路长期稳定性、表内其它数据项、数值随时间的正确性；
- 一句提醒：**组网通过 ≠ 链路可用**。复位后 CCO 的节点计数会残留，拓扑立刻就能过，表口可能还要十几分钟才恢复（真机实测教训）。

## 3. 每步要什么观测（六张表）

### ① 建档
| 项 | 内容 |
|---|---|
| 用哪个块 | `archive.add`（11H-F1 建档；档案地址 129078563412） |
| 期望的观测 | 已下发 + 收到 00H-F1 确认（默认等 5 秒）。"档案真的落地"在目标态另由查询块证明，见 §8 |
| 观测不符合 | 否认帧 / 没收到确认 → 判失败，断点＝① |
| 没拿到观测 | 串口被占、台架不可达、会话取不到 → 台架不具备，不判产品失败 |

### ①b 查档（目标态新增）
| 项 | 内容 |
|---|---|
| 用哪个块 | `archive.query`（10H-F2 读档案表；块文档属第二批） |
| 期望的观测 | 档案表**含** 129078563412（同时要求观测完整：翻页数够、总数已知） |
| 观测不符合 | 明确不含 → 失败，断点＝①b。**这是"回了确认却没落地"的唯一出口** |
| 没拿到观测 | 查询拿不到应答 / 查不全 → 不完整，不得折算成"含"或"不含" |

> 这一步在现状里是 `archive.add` 块内做的双判据。判据搬走后必须显式补这一步，否则本流程只剩"命令被接受"，抓不到假通过。

### ② 组网
| 项 | 内容 |
|---|---|
| 用哪个块 | `nwk.topology`（10H-F21 查网络拓扑，入网权威判据） |
| 期望的观测 | 入网从节点数 ≥ ceil(档案数 × 98%)；单表 → ≥1。默认严格口径 = 节点总数量 − 主节点数；最多等 300 秒、每 2 秒只读查询一次，达标即停 |
| 观测不符合 | 等满仍明确不足 → 组网没成，断点＝②。注意复位后计数残留时本步会"看起来成立"，**不能**据此认定链路可用 |
| 没拿到观测 | 档案数＝0（没有可入网目标）、或应答取不到/解析不出 → "不知道"，不算通过 |

### ③ 绑表
| 项 | 内容 |
|---|---|
| 用哪个块 | `meter.addr_probe`（02H-F1 透传 645 13H 读通信地址；单次上限 15 秒、等待预算 60 秒） |
| 期望的观测 | 收到上行帧 + 内层 645 地址域 = 123456789012。本步**只证明"STA 能取到表地址"，不是抄表** |
| 观测不符合 | 内层地址不符 / 内层没有 645 → 透传到的不是这只表（地址口径、档案），断点＝③ |
| 没拿到观测 | 等满预算一帧没有 → 链路还没恢复（首次入网最常见），断点＝③，属台架侧 |

### ④ 抄电能
| 项 | 内容 |
|---|---|
| 用哪个块 | `meter.read_645`（11H，DI 00010000；单次上限 15 秒、等待预算 30 秒——**预算写死在用例里**） |
| 期望的观测 | 收到帧 + 内层可解 + CS 合法 + DI 回显 00010000 + 数值可解（**有值即可，不校验真值**） |
| 观测不符合 | DI 不符 / CS 不合法 / 数值解不出 → 失败，断点＝④（③有观测而④有帧但 DI 不符 → 问题在数据项，不在链路） |
| 没拿到观测 | 等满一帧没有 → 链路或这一项读不通；若③刚拿过观测，更可能是后者 |

### ⑤ 抄电压
| 项 | 内容 |
|---|---|
| 用哪个块 | `meter.read_645`（11H，DI 02010100；单次上限 15 秒、等待预算 30 秒——**预算写死在用例里**） |
| 期望的观测 | 收到帧 + CS 合法 + DI 回显 02010100 + 数值可解（不校验真值）。留这一步的理由：电压是**瞬时量**，比电能更能证明"这一次真的读到了表内数据"（电能可能来自表内缓存） |
| 观测不符合 | 同④，断点＝⑤ |
| 没拿到观测 | 同④ |

## 4. 结论怎么算

- **六步观测全部符合** → 通过；
- **某步观测与期望不符** → 失败，并在结论里点明**断在哪一步**；
- **某步没拿到观测** → 台架不具备或说不清，由调用方按"是不是台架原因"再分：
  - 串口被占、服务不可达、复位窗口内链路未恢复 → **台架不具备**（产品没被证伪）；
  - 已下发、预算也给足，既无应答也无别的解释 → **说不清**，不得折算成通过。
- 一条红线：**"没拿到"既不等于通过，也不等于失败**——它必须原样上报。

## 5. 两版流程的差异（日常版 / 首次入网版）

| 项 | 日常版 `meter_daily` | 首次入网版 `meter_first_join` |
|---|---|---|
| 是否复位 STA | 不复位（日常假定链路在网，复位是物理副作用，不进主线） | 先复位 |
| 步骤数 | 6 步（含查档①b） | 7 步（再含复位） |
| 绑表等待预算 | 60 秒 | 180 秒 |
| 抄表等待预算 / 单次上限 | 每项 30 秒 / 15 秒（实测往返 2.3–2.6 秒的 6 倍余量） | 每项 30 秒 / 15 秒 |
| 主要风险 | 表口静默、DI 不符 | 复位后链路恢复是**分钟级**，前几步"没拿到"是常态 |

两点说明：**复位块的文档属第二批**，本文只说清"多一步（复位）、多等一段（链路恢复）"；**复位成立 ≠ 链路恢复**——复位判据是"下发时刻之后的会话日志命中重启指纹"，只证明板子重启了，链路是否可用仍由③④⑤证明。

## 6. 断点定位：不是"哪一步失败"，而是"哪一步没拿到观测"

| 观测长这样 | 断在哪 / 怎么读 |
|---|---|
| ①一帧都没有 / 没确认 | 建档命令通道（会话、串口、CCO），不是表的问题 |
| ①有确认但档案不含该地址 | 档案落地（目标态靠查询块；现状块内双判据会直接报出来） |
| ②应答取不到 | CCO 查询通道 / 会话 |
| ②明确不足（等满仍低于门槛） | 组网没成，或档案数不对 |
| ③有上行帧但地址不符 | 透传到的不是这只表：地址口径、档案地址换算、13H 地址域写法 |
| ③一帧没有 | 链路未恢复或透传不通（首次入网窗口内属正常） |
| ④⑤有帧但 CS 坏 / 内层不可解 | 透传内容坏了，往链路与解析上查 |
| ④⑤有帧但 DI 不符 | 答的不是这一项：请求 DI 写错，或表内无此项 |
| ④⑤有帧但数值解不出 | 链路与表正常，但数据单元不是可解的值（DI 不被支持 / 解析错） |
| ④⑤一帧没有，但③刚有观测 | 链路在，这一项读不通（DI 不被支持 / 预算太短）← 待核 |

## 7. 反例（整链层面）

- **组网过了但绑表取不到地址** → 说明"节点计数在、链路或地址口径不对"，**不能**据此说"表不在网"（复位后计数残留就是这种形态）；
- **绑表过了但抄表 DI 不符** → 说明透传链路通、表在答，问题在数据项（请求错 / 表内无此项 / 解析错），**不是**链路问题；
- **建档回了确认但档案不含** → 现状块内双判据能抓到；目标态若只有建档没有查询步，这个假通过就抓不到（见 §8）；
- **抄电能对、抄电压一帧没有** → 链路在、这一项读不通（待核：表不支持该 DI 时是回异常应答还是干脆不应答）；
- **六步都符合，但两次跑电压值不同** → **不算失败**：已定不校验数值真值（0044 §8.1-4），只要每次都解出值即可。

## 8. 与当前实现的差异（现状 → 目标）

本文描述的是**目标态**，现状仍是"块内判据"：

| 差异 | 现状 | 本文的目标态 |
|---|---|---|
| 判据位置 | 各块自己判 pass / fail / unknown / skipped | 块只报观测，本流程按 §4 比对 |
| 档案落地 | `archive.add` 内做"确认 + 回查"双判据 | 独立查询步①b 证明落地（`archive.query` 块文档属第二批） |
| 用例结论 | 执行器把块态折算成四态：通过 / 失败 / 台架不具备 / 说不清，同一用例取最严重者 | 本流程 §4 的三条规则 |
| 失败即停 | 现有编排每步"失败即停"，首个不通过步骤之后全记"未执行" | 同（断点后不再跑） |
| 等待口径 | 已实现：预算扣减、只读白名单、组网轮询达标即停 | 无差异 |

**改代码之前，本文的流程口径不生效**；现状行为以代码与用例编排为准。
