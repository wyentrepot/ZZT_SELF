# `meter.addr_probe` — 绑表取址（只观测，不判定）

> 版本 **v0.2（待审）** ｜ 所属层：原子块 ｜ 领域：抄表（STA ↔ 电表）
> 一句话：**让 STA 透传一条 645 读通信地址命令，如实返回"上行帧里的表地址是多少、有没有帧、等够没有"；不判断绑表算不算成功。**

---

## 0. 本版说明

**本块只观测，不判定。** 绑没绑对，由用例把"期望地址"和"观测到的地址"对一遍得出。

| 项 | v0.1（旧口径） | v0.2（本版） |
|---|---|---|
| 判定权 | 块内比对地址，直接出"通过 / 失败" | **块不判定**，只回观测到的地址与帧的完整性 |
| 块级结论 | 通过 / 失败 / 说不清 | 只有"拿到了观测"与"没拿到观测（并说清原因）" |
| 期望从哪来 | 期望值写死在块参数里，块同时用它对表 | 期望由调用方声明；块只报实际读数 |

**为什么改**：同一个"读地址"动作，在"新装表绑表"里期望地址相等，在"换表核对"里期望地址不等。判据留在块里，块就只能服务一种期望，另一种得另造块——块失去复用性，判据也会漂。

---

## 1. 一句话职责

**发 02H-F1（数据转发）+ 内层 645 13H（读通信地址），把上行帧里回装的表地址如实取出来。**

- 它回答：*"STA 能通到表口吗？回帧里那只表的地址是多少？"*
- 它**不**回答：*"绑表成功了吗？"*（调用方的事）
- 它**不**回答：*"抄到数据了吗？"*（抄表块的事：13H 本来就只回地址，回对了不代表读到了任何数值）

---

## 2. 做什么（执行路径）

```
调用方给出：期望表地址（12 位 645 地址，如 123456789012）、
            额外等待预算（默认 0 = 只探一次）
        │
        ▼
 ① 组一帧内嵌 645 13H（读通信地址）
    地址域口径：默认按该表地址写（本台 CCO 能据此单播转发）
                另可选全 FE 广播（645-2007 规范写法，本台实测回空帧）
        │
        ├─ 地址非法 / 等待参数非法 / 等待期想发写帧
        │        └──→ 【出口 B · 没拿到观测 · 参数非法】
        │              （绝不悄悄换成默认表地址去探）
        │
        ▼
 ② 经 02H-F1 透传下发，等上行 02H-F1 应答
    单帧应答上限：显式值 > CCO 的 t + 5 秒 > 回落 60 秒
        │
        ├─ 没有上行帧（表口静默 / 超时）
        │        ├─ 预算还没用完 ──→ 隔 5 秒重发同一条只读帧
        │        └─ 预算用完 ────→ 【出口 B · 没拿到观测 · 等待超时】
        │                          "等了 N 秒共 K 次尝试，始终没有上行帧"
        │
        ├─ 串口被占 / 台架不可达 / 会话没开
        │        └──→ 【出口 B · 没拿到观测 · 原因】（不再空转重试）
        │
        ▼ 收到上行帧
 ③ 拆外层 02H-F1，取内嵌 645，读地址域
        │
        ├─ 内层没有 645 报文 / 地址域取不出 / 解不开
        │        └──→ 【出口 B · 没拿到观测 · 观测不完整】
        │              （如实说"帧收到了，但取不到地址证据"）
        │
        └─ 取到 12 位地址域 ──→ 【出口 A · 观测：实际地址 = …】
                               （等不等于期望，块不评论）
```

**图上没有"通过 / 失败"** —— 两个出口给的都是事实，结论归调用方。

**两条口径要记住**：真机实测复位 STA 后表口静默十几分钟到半小时，这段时间"读不到"既不能算成功也不算设备失败，块只能如实报"等了多久、试了几次、始终没有帧"；反过来，链路上出现过一条地址不对的回帧就是已经发生过的事实，哪怕最后一轮没帧，也不能把"有帧那次的读数"换成"等待超时"。

---

## 3. 返回什么（观测三件套）

| 返回项 | 取值 | 说明 |
|---|---|---|
| **观测值** | 上行帧内嵌 645 的地址域（12 位）/ 外层"通信协议类型" / 是否收到上行帧 / 第几次尝试拿到 / 等待秒数 / 本次请求用的地址口径 | 地址是**应答回装**的，不是请求里抄回来的 |
| **完整性** | 只看了一帧 / 只探了一次 / 内层有没有解出 645 / 地址域有没有取到 / 等待是否等满 | 只探一次就必须说"只探了一次"，不许让调用方误以为等过 |
| **没拿到时的原因** | 串口被占 / 台架不可达 / 等待超时（全程无帧）/ 参数非法 / 观测不完整 | 只描述"为什么没拿到"，不描述"算不算失败" |

三类"没拿到"要分清：**一帧都没回**（等待超时）、**回帧但内层取不出地址**（观测不完整）、**根本没下发**（参数非法 / 串口被占 / 台架不可达）。**没有"说不清"这个块级结论**：块只有两种处境——拿到了观测，或者没拿到并说清为什么。

---

## 4. 调用方怎么判（三个典型用法）

| 用法 | 用例声明什么期望 | 谁来判 |
|---|---|---|
| 绑表（`meter_daily` 第 3 步、`meter_first_join` 第 4 步） | 拿到了观测，且实际地址 = 期望表地址 | 用例 |
| 换表核对（拿错表 / 档案还是旧地址） | 拿到了观测，且实际地址 ≠ 期望表地址 | 用例 |
| 复位后等链路（`wait_s` 给到 180 秒） | 拿到了观测；若报等待超时，是续等还是判失败由用例决定（块不知道链路该多久恢复） | 用例 |

**同一个读数在第二行期望"≠"** —— 这就是判据必须归调用方的原因。还要记住两条边界：**绑表通过 ≠ 抄表通过**（13H 只证明能取到地址，不证明能读到数值，链路真可用必须再接一次读数据）；**组网通过 ≠ 绑表通过**（复位后 CCO 节点计数残留，拓扑块可能立刻达标而表口仍静默）。

## 5. 参数

| 参数 | 含义 | 默认值 |
|---|---|---|
| 表地址（meter_addr） | 12 位 645 地址；既是请求地址域的来源（默认口径下），也是调用方要比的期望值 | 取配置默认（出厂 `123456789012`） |
| 通信协议（protocol） | 2 = 645-2007，1 = 645-1997 | 2 |
| 请求地址域口径（addr_mode） | 按该表地址写 / 全 FE 广播 | 按该表地址写 |
| 单帧应答上限（expect_timeout） | 等一帧上行应答的秒数 | 显式值 > CCO 的 t + 5 秒 > 回落 60 秒 |
| 额外等待预算（wait_s） | 表口静默时最多等多久，等满才收工。**等待预算必须由用例写死**（0044 §8.1-3），块默认 0 仅作兜底 | 0（只探一次） |
| 重试间隔（poll_interval_s） | 两次尝试之间隔多久 | 5 秒 |

**等待预算为什么默认 0**：日常链路已在网时，一次透传本来只要 2.3~2.6 秒，等是白等；复位后链路恢复是分钟级，那时才需要预算。开与不开必须是调用方的显式选择——用例不写就按"只探一次"，与旧行为逐字一致（**0044 §8.1-3 起：等待型步骤必须在用例里写死预算，块默认值只作兜底**）。

**单帧应答上限为什么是"t + 5 秒"**：t 是 CCO 侧"从节点监控最大超时时间"，由 03H-F7 查一次（同一次运行只查一次，查询本身等 6 秒）。用例里显式钉了 15 秒就不再查 t，避免按 t（90 秒）+ 5 秒空等；15 秒 = 实测往返的 6 倍余量。

**两条纪律**：**给了但不合法 ≠ 没给**（非法地址报参数错，绝不静默换成默认表地址，否则"传错地址"会变成"拿默认那只表去判"）；**一次只探一只表**（多只表就多跑几次，块不猜先探哪只）。

## 6. 副作用

| 项 | 内容 |
|---|---|
| 副作用等级 | **只读**（等待期只重发 645 11H 读数据 / 13H 读通信地址） |
| 为什么只读重要 | 等待期会把同一条透传帧重发几十次。一旦 payload 是写帧（冻结 12H、写数据 14H），"等链路恢复"就变成**反复对表下发写动作**——可能冻结掉正在做的抄表、改写表内数据 |
| 硬闸门 | 等待预算大于 0 时先验内层控制码，不是只读帧直接拒绝下发；看不出控制码也拒绝（宁可不发，不拿台架赌） |
| 需要留意的一处 | 调用方可以显式塞一条内嵌 645 报文进来。塞的是写帧且等待预算为 0 时，块会照发一次——**这时的写动作是调用方给的动作，不是块造的**，用写帧请务必保持预算为 0 |
| 收场手段 | 不需要（读地址不改变设备状态） |

## 7. 反例（怎么证明它没撒谎）

判据搬走之后，块要证明的是**观测本身的正确性**：

| # | 构造方式 → 期望观测 | 防的是什么 |
|---|---|---|
| R1 | 正常链路，表回自己的地址 → 观测"实际地址 = 期望地址、协议类型 2" | 拿请求里写的地址冒充应答证据（判据只认应答回装的地址域） |
| R2 | 档案还是旧地址、表已换新 → 观测"实际地址 = 新地址，与期望不同"，不判 | 把"地址不符"藏起来，或直接说成设备坏 |
| R3 | 复位 STA 后立即探测、预算 180 秒 → 观测"等了 180 秒共 K 次尝试，始终没有上行帧" | 把"没有帧"记成"地址不符"（那是两件不同的事） |
| R4 | 中途回了一帧错地址、后面全静默 → 观测保留"有帧那次的读数" | 重试把真失败洗成"等待超时"，假 PASS 的来源 |
| R5 | 传 5 位地址 → 观测"参数非法、未下发"，不动默认表 | 静默换成默认表去探、去判 |
| R6 | 请求地址域切成全 FE 广播 → 观测"帧收到、内层没有 645 报文（空数据单元）" | 把地址口径问题读成"设备地址错" |
| R7 | 塞一条写帧并给等待预算 → 观测"参数非法、未下发" | 等链路恢复时反复对表下发写动作 |

R1、R3、R4 是必须项。

## 8. 明确不做什么

- **不判定通过 / 失败**（调用方的事）；
- **不判抄表数值**（读数据块的事：13H 只回地址，不含量值）；
- 不判真实可达 / 在网数（在网块的事）；
- 不建档、不改档案地址（档案块的事）；不重试写帧、不做任何写动作（只读闸门的事）；
- 不替用例猜等待预算（默认 0 = 只探一次）。

---

## 9. 调用方义务（必须写进用例规范）

判据搬到调用方之后，保护不会自动发生。因此：

> **凡以"绑表成功"为目的的用例，必须显式声明"期望：实际表地址 = 指定地址"，并同时断言"拿到了观测"。**
> 只跑本块、不写期望值的用例，视为缺判据，不得入库。

另外两条：**绑表通过必须再由一次读数据补证链路可用**（否则"组网通过 + 绑表通过"仍可能在表口静默时假 PASS）；**等待预算写在用例里**（复位类场景给到分钟级，现网用例给 180 秒；日常回归保持 0——块默认值不能替用例表达"这一步等多久是可接受的"）。

## 10. 与当前实现的差异（待改代码）

本文写的是**目标契约**。现有代码仍是旧口径，差在六处：

| 差异 | 现状 | 目标 |
|---|---|---|
| 谁来判 | 块内比对地址，直接出"通过 / 失败 / 拿不到结论" | 块只回"实际地址 + 完整性"，判据搬到调用方 |
| 地址不符 | 块判"失败" | 报两个地址（实际 / 期望），由用例判 |
| 回帧但内层无 645 | 块判"失败"，而事实口径判"不知道"——同一现象两个结论 | 块只报"帧收到、取不到地址证据"，不再替调用方定性 |
| 全程无帧 | 块记"不知道"（块级说不清） | 报"没拿到 · 等待超时"，并带出等了多少秒、几次 |
| 参数非法 | 也走"拿不到结论"这条道，与设备行为混在一起 | 单独报"未下发 · 参数非法" |
| 事实出口 | 只有地址相符时才给"STA 已知该表地址"，不符时给不出"否" | 由调用方判；事实口径是否要能出"否"，见 §12 |

**改代码之前，本文档描述的契约不生效**；现有代码行为以代码为准。审过之后一并迁移。

## 12. 待确认

**请你定四件事**：

1. **请求地址域默认口径**：默认"按该表地址写"（本台 CCO 能过），而规范写法是全 FE 广播（本台 CCO 回空帧）。换 CCO / 换省份时默认值要不要强制切换？
2. **等待预算给谁定**：`meter_daily` 给 60 秒、`meter_first_join` 给 180 秒，而真机复位后恢复可达十几分钟到半小时；块声明里又写着"`meter_daily` 保持默认（0）"——三处口径不一致，需要拍板。
3. **"地址不符"够不够判绑错表**：要不要强制用例再抄一次数据交叉确认，还是地址不符即可结论？
4. **事实出口的"否"**：地址不符时，"STA 已知该表地址"这条事实应该给"否"还是"不知道"（现状只有相符才给"是"）？

**另有一处待核**：`meter_daily` 的用例说明写"应答等待上限显式钉 15 秒"，但计划里还额外给了 60 秒等待预算，说明文字没提——两处措辞需要对齐（以计划里的实际参数为准）。
