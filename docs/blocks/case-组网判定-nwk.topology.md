# `nwk.topology` — 查询网络拓扑（只观测，不判定）

> 版本 **v0.2（待审）** ｜ 所属层：原子块 ｜ 领域：组网（CCO）
> 一句话：**发 10H-F21 取一次节点读数，如实返回"看到多少节点、门槛多少、看全没有"；不判断这次组网算不算通过。**

---

## 0. 本版说明

**本块只观测，不判定。** 一次组网算不算通过，由用例把"期望"和"观测"对一遍得出。

| 项 | v0.1（旧口径） | v0.2（本版） |
|---|---|---|
| 判定权 | 块内算门槛并直接出"通过 / 失败" | **块不判定**，只回读数；门槛值一并回传，供调用方核对 |
| 块级结论 | 通过 / 失败 / 说不清（不知道） | 只有"拿到了观测"与"没拿到观测（并说清原因）" |
| 等待期 | 单帧一刀切，看到就定 | 反复只读探测，达标即停、等满预算才收工 |
| 历史缺陷 | 曾把"档案数"当"在线数"，判出假 PASS | **档案数与在网数分开报**，读数与门槛都写进观测 |

**为什么改**：同一个读数，在"新装表等入网"里期望达标，在"拔表等离网"里期望不足。判据写在块里，块就只能服务一种期望，另一种得另造一个块——块失去复用性，判据也会随用例漂移。

---

## 1. 一句话职责

**发 10H-F21（查询网络拓扑信息）取一次节点读数，返回"看到多少、门槛多少、看全没有"。**

- 它回答：*"CCO 现在报的节点总数量是多少？主节点几个？本模块档案里应有几个从节点？门槛是多少？"*
- 它**不**回答：*"这次组网算不算通过？"*（调用方的事）
- 它**不**回答：*"节点真的能被抄到吗？"*（真实可达由 `nwk.nodes_online` 用另两路证据查）

---

## 2. 做什么（执行路径）

```
调用方给出：等待预算（默认 300 秒）、口径（默认严格：只算从节点）
        │
        ▼
 ① 一轮只读探测（两帧，各 5 秒应答上限）
    10H-F1  → 档案数（路由档案里的从节点总数量）
    10H-F21 → 节点总数量 + 逐节点记录（据此数主节点 CCO）
        │
        ├─ 有一帧拿不到（无应答 / 串口被占 / 台架不可达）
        │        └──→ 【出口 B · 没拿到观测】
        │              原因：串口被占 / 台架不可达 / 等待超时 / 参数非法
        │              ※ 绝不把"没看到"写成"0 个节点"
        │
        ├─ 档案数 = 0
        │        └──→ 【出口 A · 观测：没有可入网目标】
        │              （这是事实，不是"一个都没入网"）
        │
        ▼ 两帧都拿到可判定读数
 ② 算门槛 = 档案数 × 98%，向上取整（100 只表 → 98）
    读数 = 节点总数量 − 主节点数（默认严格口径）
        │
        ├─ 读数 ≥ 门槛 ───────────→ 【出口 A · 观测：达标】
        │                           （成功路径最多等 2 秒）
        │
        ├─ 读数 < 门槛，未等满 ───→ 隔 2 秒回到 ①（只发只读查询）
        │
        └─ 读数 < 门槛，等满 300 秒 → 【出口 A · 观测：明确不足】
                                    带出实测、门槛、等了多久、探了几次
```

**图上没有"通过 / 失败"** —— 两个出口给的都是事实，结论归调用方。

**为什么默认要减主节点**：主节点 CCO 本来就一定在。把它算进分子，12 只表里只有 11 只从节点入网（91.7%）也会读成"达标"，属漏判。KB 原句"节点总数量 = 档案个数的 98%~100%"是验收线的意图，不是让主节点混进分子；要逐字照原句比较，调用方显式打开"含主节点"口径即可。

**为什么默认等 300 秒**：台架实测一轮入网约 4 分钟。单帧一刀切会把"还在入网"读成"明确不足"——那是块自己造出来的假失败。

## 3. 返回什么（观测三件套）

| 返回项 | 取值 | 说明 |
|---|---|---|
| **观测值** | 节点总数量 / 主节点数 / 在网从节点数 / 档案数 / 门槛 / 本次应答节点数 / 探测次数 / 等待秒数 | 两种口径的读数都带出，人工复核不必再算 |
| **完整性** | 是否按节点总数量**翻页取全**（一页不够就翻页直到取满）/ 主节点数是否取全 / 等待是否等满 | 翻了页仍没取全，必须如实说"只取到 N / 总数 M"，且**不得**按已取到的部分算主节点数 |
| **没拿到时的原因** | 串口被占 / 台架不可达 / 等待超时 / 参数非法 | 只描述"为什么没拿到"，不描述"算不算失败" |

三种"没拿到"要分清，别混成一句"不知道"：**一帧都没回**（等待超时）、**回帧但解析不出节点读数**（观测不完整）、**查询根本没能下发**（串口被占 / 台架不可达 / 参数非法）。**没有"说不清"这个块级结论**：块只有两种处境——拿到了观测，或者没拿到并说清为什么。至于"没拿到"意味着什么，是调用方结合自己的期望来判断的。

## 4. 调用方怎么判（三个典型用法）

| 用法 | 用例声明什么期望 | 谁来判 |
|---|---|---|
| 入网成功（`nwk_join`、`meter_daily` 第 2 步） | 拿到了观测，且在网从节点数 ≥ 门槛 | 用例 |
| 拔表后应掉网（未来用例） | 拿到了观测，且在网从节点数 < 门槛（等满预算）；若读到 0 个节点而档案数仍是 12，还要用档案块确认档真的删过 | 用例 |
| 清库后跑组网 | 观测是"没有可入网目标"；这种观测算"不适用"还是"通过"，块不管 | 用例 |

**同一个读数，第一行期望"≥"、第二行期望"<"——这就是判据必须归调用方的原因。**

## 5. 参数

| 参数 | 含义 | 默认值 |
|---|---|---|
| 等待预算（wait_s） | 最多等多久；等满仍不足才收工 | 300 秒 |
| 探测间隔（poll_interval_s） | 两轮之间的间隔 | 2 秒 |
| 节点起始序号（start） | 从第几个节点开始查，1 起编号 | 1 |
| 查询条数（count） | 一页要回多少条节点记录；**总数超过它时自动翻页取全**（0044 §8.1-2） | 32（合法 1~255） |
| 验收比例（min_ratio） | 门槛 = 档案数 × 该比例，向上取整 | 0.98 |
| 主节点是否计入（master_included） | 关 = 严格口径（减主节点）；开 = 照 KB 原句直接用节点总数量 | 关 |
| 单帧应答上限（expect_timeout） | 每一帧等应答的秒数 | 5 秒 |

三条纪律：

1. **等待预算写进用例**：块的 300 秒是给"没人管时也别乱判"兜底，不是让用例依赖块默认值——默认值漂了，用例的结论就跟着漂；
2. **档案数只认 10H-F1 的第一字段**：不用 10H-F4 里的那份（那是 16 字节路由运行状态结构体里的一个字段，有长度门限的历史缺陷）；
3. **门槛向上取整要吃掉浮点误差**：100 × 0.98 在机器里是 98.00000000000001，直接向上取整会得到 99，把 98% 抬成 99%。

## 6. 副作用

| 项 | 内容 |
|---|---|
| 副作用等级 | **只读**（等待期只发 10H-F21 / 10H-F1 / 10H-F4 / 10H-F2 查询） |
| 为什么只读重要 | 300 秒 / 2 秒 ≈ 150 轮 × 2 帧 ≈ 300 帧。若等待里混进"重启路由"或"重开注册窗口"这类写帧，就会在等组网的 5 分钟里反复把设备打回起点——组网永远不收敛，看起来还像"设备入不了网" |
| 硬闸门 | 等待期每帧下发前检查一次，非只读帧**一帧都不发**，并把"被哪条白名单拒绝"写进观测（不是先发后拦） |
| 收场手段 | 不需要（没有写动作，不改变任何设备状态） |

## 7. 反例（怎么证明它没撒谎）

判据搬走之后，块要证明的是**观测本身的正确性**：

| # | 构造方式 → 期望观测 | 防的是什么 |
|---|---|---|
| R1 | 12 只表档案，只有 11 只从节点在网 → 观测"节点总数量=12、主节点 1、在网从节点 11、门槛 12、明确不足" | 主节点混进分子，把差一个判成达标 |
| R2 | 档案为空（清库后）→ 观测"档案数=0、没有可入网目标"，不给门槛、不判 | 把"没有目标"写成"入不了网"，或被当成通过 |
| R3 | 串口被占（会话忙）/ 模拟集中器不可达 → 观测"块未执行 + 原因"，不产出任何节点数字 | 把环境问题伪装成"0 个节点在线" |
| R4 | CCO 对 10H-F21 始终无应答 → 观测"未拿到 · 等待超时：等了 300 秒、只读探测 K 次，始终没有可判定的应答" | 静默超时被读成"节点数=0" |
| R5 | 档案 100 只、CCO 回节点总数量 100 → 门槛读数必须是 98，不是 99 | 浮点误差把 98% 抬成 99%，差一只表就无解 |
| R6 | 构造一次"等待期夹一个写帧"的调用 → 观测"参数非法，未下发" | 5 分钟里反复重启路由，把台架打乱 |
| R7 | 节点总数量 40、单页只回 32 条 → 必须继续翻页取全 40 条再数主节点；翻页中途失败 → 观测标"只取到 32 / 总数 40，观测不完整"，**不得**按 32 条算主节点数 | 主节点数读成 0、分子虚高，把"差一个"判成达标 |

R1、R3、R4 是必须项。

## 8. 明确不做什么

- **不判定通过 / 失败**（调用方的事）；
- **不判真实可达**（那是 `nwk.nodes_online` 用 10H-F4「已抄从节点数量」+ 10H-F2「信号品质>0」两路交叉的事）；
- 不下发任何写帧（不重启路由、不重开注册窗口）；
- 不建档、不删档（档案块的事）；
- 不判断链路能不能抄到表（抄表块的事）；
- 不替用例设等待预算（用默认值只是兜底）。

---

## 9. 调用方义务（必须写进用例规范）

判据搬到调用方之后，保护不会自动发生。因此：

> **凡以"组网成功"为目的的用例，必须显式声明"期望：在网从节点数 ≥ 门槛"，并同时断言"拿到了观测"。**
> 只有块状态、没有期望值的用例，视为缺判据，不得入库。

另外两条也要写进规范：**组网通过 ≠ 链路可用**（复位 STA 后 CCO 节点计数会残留，拓扑可能立刻达标，而表口还要十几分钟才恢复，链路可用必须由绑表 + 抄表补证）；**等待预算写在用例里**，不要靠块默认值，否则块默认一改，用例结论跟着变而没人察觉。

## 10. 与当前实现的差异（待改代码）

本文写的是**目标契约**。现有代码仍是旧口径，差在六处：

| 差异 | 现状 | 目标 |
|---|---|---|
| 谁来判 | 块内算门槛，直接出"通过 / 失败 / 不知道"，并把期望值也一起写死 | 块只回读数与门槛，判据搬到调用方 |
| 块级结论 | 有"通过 / 失败"两种块状态 | 两件事：拿到了观测（含读数与完整性）+ 没拿到（含原因） |
| 参数非法 | 起始序号 / 条数 / 比例 / 帧不匹配时记"失败" | 记"未下发 · 参数非法"，与设备行为分开 |
| 明确不足 vs 没有读数 | 都折算进块状态，调用方容易混看 | 必须分成"读到数但不到门槛"与"根本没读到数" |
| 主节点取全 | 只在本页数主节点；总数超过查询条数时静默偏小 | **按总数翻页拉全后再数**；取不全则标观测不完整（0044 §8.1-2 已定） |
| 声明里的断言 | 块声明写着"按 98% 判"，但那条断言没有任何代码执行——真正的判定硬写在块里 | 块声明只描述观测口径，断言由用例声明并执行 |

**改代码之前，本文档描述的契约不生效**；现有代码行为以代码为准。审过之后一并迁移。
