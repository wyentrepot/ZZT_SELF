## 一、问题：为什么不能"每页各自软件化"

v3 把模拟集中器单页做成了软件壳（菜单栏 + 侧栏 + 四工作区 + Dock + 状态栏）。如果 9 个页面各套一层：

1. **双左栏**：生产外壳本来就有分组侧栏（验证/设备/辅助/维护），页内再来一条侧栏，左侧出现两条竖轨；
2. **菜单栏打架**：页内菜单栏与外壳顶栏重叠，快捷键（Ctrl+B 等）两套语义；
3. **底部横条复活**：侦听台的收发记录、模块日志的日志流、simcon 的收发记录本是同类"示波器"，各页各自为政就退回了老问题。

## 二、搭配方案：骨架上升一层，模块变成壳内工作区

```
┌────────────────────────── 菜单栏（全局唯一）────────────────────────────┐
│ SC·工作台   会话 数据 视图 帮助                    [●COM3 已连接] [主题] │
├──────────┬─────────────────────────────────────────────────────────────┤
│ 模块导航  │ 二级页签（模块内视图切换，位置恒定）                          │
│          │─────────────────────────────────────────────────────────────│
│ 验证      │                                                            │
│  ·验证台  │                                                            │
│ 设备      │                    模块工作区                                │
│  ·侦听台  │            （每个模块独占全宽全高）                           │
│  ·模块日志│                                                            │
│  ·模拟集中器│                                                          │
│  ·串口配置│                                                            │
│ 辅助      │                                                            │
│  ·报文追踪│                                                            │
│  ·协议字典│                                                            │
│  ·场景脚本│                                                            │
│ 维护      │                                                            │
│  ·工作台状态│                                                          │
│ «折叠(Ctrl+B)                                                          │
├──────────┴─────────────────────────────────────────────────────────────┤
│ 全局 Dock：帧日志 │ 日志流 │ 事件        TX 12 RX 11        ▾折叠(Ctrl+J) │
├─────────────────────────────────────────────────────────────────────────┤
│ 状态栏：module_log ✓ · listener ✓ · COM3 9600,E · TX/RX · 最新帧 · 主题  │
└─────────────────────────────────────────────────────────────────────────┘
```

五条恒定骨架（用户肌肉记忆）：

| 骨架 | 职责 | 吸收了哪些旧元素 |
|---|---|---|
| 菜单栏 | 全局低频动作：会话（串口/Profile）、数据（导入/导出）、视图（主题/侧栏/Dock）、帮助（口径/快捷键） | 各页顶栏的串口参数行、Profile 选择 |
| 侧栏 | **模块导航**（沿用生产壳四组 9 项）+ 折叠 | 外壳侧栏原职责，视觉升级 |
| 二级页签 | 模块内视图切换，恒定在工作区顶部同一条线 | 侦听台 5 视图页签、模块日志 3 页签、simcon v3 四工作区（降级为页签） |
| 全局 Dock | 帧日志 / 日志流 / 事件——跨模块"示波器"，谁下发谁推送，可折叠可拖高 | simcon 收发记录、侦听台帧日志、模块日志日志流 |
| 状态栏 | 服务健康（module_log ✓ / listener ✓）、串口会话、TX/RX、最新帧 | 外壳副标题状态、各页状态芯片 |

关键语义：
- **一级=模块，二级=视图**：侦听台 5 视图、模块日志 3 页签、simcon 4 工作区都放二级页签，不再有页内侧栏；
- **Dock 是全局资产**：在 simcon 下发、在侦听台回放、在模块日志烧录，帧日志都进同一个 Dock（可按来源着色/过滤）；
- **模块切换不销毁**：沿用生产壳 iframe 保活 + hash 路由 + 主题广播（0.6/0.7/0.8 三项机制原样保留），换的只是壳的骨架视觉。

## 四、回答"搭配 or 只更新集中器"

**推荐：方向统一壳，落地分两步。**

- **第一步（建议先做）**：全局壳骨架（菜单栏/侧栏/全局Dock/状态栏）+ 模拟集中器四工作区 + 三个轻模块（报文追踪/协议字典/场景脚本）换肤。理由：轻模块本来就是三列布局，换壳成本≈0；simcon 已有 v3 细化方案；这一步完成后"软件感"立即成立。
- **第二步**：侦听台（29 项）与模块日志（21 项）平移进壳——两者保留现页内部逻辑（iframe 保活机制不动），只把页内头部/页签改造为二级页签条，收发记录/日志流接入全局 Dock。
- **若坚持"暂时只更新集中器"**：v3 可以独立跑在现有壳的 iframe 里（现壳已有侧栏折叠），代价是双左栏 + 页内菜单栏与外层顶栏并存，属过渡态可接受但不建议长期。

## 五、落地路线（延续 v3 §七，机制零破坏）

1. `index.html`（壳）换骨架：菜单栏 + 侧栏视觉升级 + 全局 Dock + 状态栏；iframe 保活/路由/主题广播**一行不改**；
2. 新增全局 Dock 的 `postMessage` 协议：子页面向壳推帧日志行（`{type:"wb-dock-frame", dir, afn, fn, hex}`），simcon/侦听台/模块日志逐步接入；
3. simcon 页去头部改四页签（v3 §七的 render 平移法）；轻模块三列页换肤；
4. 侦听台/模块日志第二步平移；
5. 每步按功能核对表回归（94 项逐条）。
