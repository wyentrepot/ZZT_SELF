设计说明

一、为什么去掉渐变和玻璃拟态

原方案用 --bg-gradient + backdrop-filter: blur(8px) 铺满全屏。在报文表格场景中，模糊背景会让 11px 的等宽字符边缘发虚，长时间盯屏的眼动成本显著上升。新方案改为四级纯色表面 + 1px 发丝描边，用明度差而非阴影建立层次——这也是 VS Code、Grafana、Linear 的共同选择。

二、状态五态独立色相（关键修复）

原 tokens.css 第 345 行：.badge.inconclusive 与 .badge.run 共用 warn 配色，仅靠 opacity:0.85 区分。而 inconclusive（证据缺失、无法判定）与 warn（有告警但已跑完）在测试结论里语义完全不同。

新方案把 inconclusive 提升为独立紫色语义位，与 pass/fail/warn/run 平级。流水线里可以看到六个步骤各自的状态色：通过绿、失败红、不确定紫、告警黄、进行中蓝、跳过灰。

三、解决「导航不直观」

  • 8 个页面按作业流顺序分组：观测 → 执行 → 资源 → 系统，而不是平铺
  • 组标题使用大写小字 + 字距，弱化到「扫视时不抢注意力，需要时能定位」
  • 顶栏 Ctrl+K 直达：输入「侦听」「串口」即可过滤导航
  • 激活态用左侧 2px 强调条，折叠后仍可辨识

四、解决「信息密度低」

  • 表格行高从 ~44px 压到 28px（紧凑模式），字号 12px，表头 sticky
  • 几乎所有页面改为主从分栏（列表 + 详情），而非卡片纵向堆叠
  • 顶栏常驻状态条，把「设备链路 + 队列 + 最近结论」压进 32px 高度
  • 提供紧凑 / 舒适密度切换（顶栏按钮），适配不同屏幕与视力

五、解决「状态不清晰」

  • 顶栏下全局状态条：COM4 / COM24 / 集中器 / 模块 四路链路实时点阵，无需进页面就知道能不能开工
  • 验证工作台用横向流水线表达 6 阶段，每步独立状态 + 耗时，比单一「运行中」徽章信息量高一个量级
  • 结论徽章区分 pass / fail / inconclusive，后者会提示「证据缺失，需人工复核」
  • 空态不再只写「无数据」，而是说明下一步该做什么

六、交互约定

  • 所有主操作按钮固定在页面头部右侧，不随内容滚动
  • 危险操作统一收进红色边框区域，按钮二次确认
  • 等宽字体仅用于 ID、偏移、十六进制、时间戳，正文保持无衬线
  • 数字统一 tabular-nums，表格里纵向对齐

七、还没做的（等你定）

  • 响应式：当前按 ≥1280px 桌面设计，未做窄屏兜底
  • 浅色主题：Token 已按变量组织，加一套 [data-theme=light] 即可
  • 无障碍：焦点环已有，但未做完整 ARIA 与对比度审计
  • 本 Demo 未接任何后端，所有数据为模拟
