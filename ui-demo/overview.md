```
先清单  →  后设计  →  再核对
```

   `功能清单.md` —— **9 个页面 + 外壳，共 94 项功能点**。这是唯一功能基线，禁止凭印象增删。

3. **再核对**：产出 `功能核对表.md`，94 项逐条指认落点，并用两套脚本自动校验。

**核对结果：94 / 94 覆盖（✅ 93 · ⚠️ 1）**

## 三、设计基线（沿用你已确认的方向）

| 决策项 | 选择 |
|---|---|
| 视觉基调 | 深色专业仪表盘 |
| 覆盖范围 | 全套外壳 + **9 页**（v1 漏了场景脚本页） |
| 交付形态 | 单文件 HTML（假数据，双击即开） |
| 待解决痛点 | 导航不直观 / 信息密度低 / 状态不清晰 |

### 1. 视觉语言：四级纯色表面 + 1px 发丝描边

去掉原 `tokens.css` 的 `--bg-gradient` + `backdrop-filter: blur(8px)` 全屏铺底，改用明度差建立层次。
理由很实际：报文表格里 11px 等宽字符在模糊背景上边缘发虚，长时间盯屏成本高。

### 2. 状态五态独立色相（关键修复）

生产 `tokens.css` 中 `.badge.inconclusive` 与 `.badge.warn` 共用配色，只靠 `opacity` 区分 ——
但「证据缺失、无法判定」和「有告警但已跑完」是完全不同的语义，会导致误判。
v2 把 inconclusive 提升为**独立紫色语义位**：

| 状态 | 色值 | 含义 |
|---|---|---|
| pass | `#3FB950` 绿 | 通过 |
| fail | `#F85149` 红 | 失败 |
| **inconclusive** | **`#A371F7` 紫** | **证据缺失，需人工复核** |
| warn | `#D29922` 琥珀 | 非关键告警 |
| run | `#4C8DFF` 蓝 | 进行中 |
| idle | `#5A6678` 灰 | 未执行 / 跳过 |

### 3. 导航：按作业流四分组

- **验证**：验证工作台
- **设备**：串口配置 · 模块日志 · 侦听台 · 模拟集中器
- **辅助**：报文追踪 · 协议字典 · 场景脚本
- **维护**：工作台状态

配套：hash 路由（可深链 / 刷新 / 前进后退）、`Ctrl+B` 折叠侧栏、激活态左侧强调条。

### 4. 4 套主题

深蓝科技 / 暗色翡翠 / 炭黑灰金 / 靛蓝玻璃，配色取自生产 `apps/workbench/static/tokens.css`。
切换后通过 `postMessage({type:'wb-theme-change'})` 广播给子页面，「工作台状态」页同步显示当前主题名。

### 5. 信息密度

- 表格行高 28px（紧凑），字号 12px，表头 sticky
- 页面普遍改**主从分栏**（列表 + 详情侧栏），替代卡片纵向堆叠
- 顶栏密度切换（紧凑 / 舒适）
- 窄屏（<860px）侧栏转抽屉 + 遮罩，Esc 关闭且焦点回归
