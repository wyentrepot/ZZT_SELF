## 1. 问题定义

监听场景的核心诉求：以**一次发送的特征**锁定一条通信流，自动判定三段事实——

| 阶段 | 业务问题 | 判据（全部为侦听台空口自证） |
|---|---|---|
| S1 发出 | CCO 有没有发出去 | 匹配特征的下行帧被侦听台捕获 |
| S2a 收到 | STA 有没有收到 | 链路层 ACK 帧（4-2 选择确认，DLL 已解析为 FrmType='ACK'） |
| S2b 响应 | STA 有没有响应 | **同报文序号**的上行帧（4-3 协议保证配对） |
| S3 已接收 | 响应有没有被 CCO 接收 | ① 0x0020 确认/否认帧（序号直接指认，**铁证**）；② 重传反证：窗口内同序号下行未重发（**推断**） |

失败定位与成功同等有价值：无 ACK=信道层丢帧；有 ACK 无响应=STA 业务层卡滞；有响应但 CCO 重发=CCO 接收侧异常。追踪输出的是"断在哪一跳"，不是二值 pass/fail。

## 2. 协议依据（确凿）

| 协议事实 | 出处 | 在本设计中的角色 |
|---|---|---|
| 报文序号（2B）：请求/应答配对，**递增、重发不增** | 4-3 通用报文结构 | ① 请求↔响应配对主键；② "轮"的天然标识；③ 重传=同序号下行复现 |
| 抄表应答报文序号"**与下行报文序号一致**" | 4-3 §抄表应答 | 配对是协议义务，非启发式 |
| 下行报文携带**设备超时时间**（100ms 单位，采集器=电表×2）与配置字 **bit4~7：未应答重试标志/否认重试标志/最大重试次数** | 4-3 §抄表下行 | 响应窗口与预期重试次数从帧内参数推导，AI 无需懂协议 |
| **确认/否认 0x0020**：序号域=所确认目标报文的报文序号 | 4-3 §4.6 | S3 显式证据（上报/注册类业务的回执） |
| 链路层**选择确认帧**（定界符类型 2） | 4-2 | S2a 链路级证据 |
| **原始源/最终目的 TEI**（12b，跨信道转发不变） | 4-2 | 中继场景的关联与观测键 |
| STA 主动上报不需要应答，由 **CCO 回 0x0020** | 4-3 §事件上报 | 上报类业务是反向流：STA 发起→CCO 确认 |

## 3. 真机数据实证（设计可行性锚点）

侦听台 DLL 解析输出已具备全部原材料（frames 表 summary_json 实测字段）：

- **业务名直出**：FrmType=「终端主动并发抄表/台区户变关系识别/心跳检测/发现列表/代理信标/ACK/关联请求/网间协调」——应用层业务在链路层帧名上已可区分；
- **应用层已拆出**：`APP_PORT`（端口 0x11…）、`APP_ID`（报文 ID）、`APP_RAW`（4-3 载荷原文）；
- **TEI 齐全**：`SRC/DST`（逐跳）+ `ORI_S/FINL_D`（原始源/最终目的，中继不变）；另有 `SNID`、`ChType`（PLC/RF）、`RSSI`、`RxFchTime`；
- **并发抄表真机样本**（同序号 0x0201 一轮，44.4 秒）：下行 63 帧 → TEI{006,087,0D8,140,**FFF(广播)**,…}、表地址 13 个；上行 8 帧 ← 5 个 STA、覆盖 4 个表地址。请求/响应载荷共享业务头前缀（`1103 0000 0102 …`），自 645 控制字节起分叉（下行 0x33 / 上行应答码）。

由此得出的三条设计性结论：

1. **一轮 = 同报文序号的全部帧集合**——协议自带任务号，分组无需启发式；
2. **单播与广播在同一轮内混合出现**（FFF 与具体 TEI 并存），引擎不得假设轮内同质；
3. **轮耗时（44s）≫ 单表设备超时（5.1s）**——轮闭合窗口必须独立于单表超时推导（见 §5）。

## 4. 核心模型

### 4.1 三层粒度

| 粒度 | 特征构成 | 回答的问题 | 输出 |
|---|---|---|---|
| **flow** | 业务ID + 报文序号 + 对端表地址 | 这一次请求-响应成没成？ | 单条证据链 |
| **round** | 业务ID + 报文序号 + **时间簇** | 这一轮任务，哪些表回了/没回/断在哪跳？ | 按表地址的子流列表 + 位图汇总 |
| **campaign** | 仅业务ID（不带序号） | 时间窗内该业务的整体质量？ | 窗口内每个 (序号×时间簇) 自动各立一轮 → 多轮聚合 |

> **校准修正（§10 实测）**：真机样本显示报文序号跨 5 小时不递增（0x0003 恒为 0x0201），其语义更接近"业务任务号"而非逐轮递增的流水号。因此 **round ≠ 同序号帧集合**，而是 **(报文序号 × 时间簇)**：按空闲间隔切簇（缺省 60s 无该序号帧即开新轮，可配置），重传判定与 S3 反证均在时间簇内进行。

### 4.2 对账单位 = 表地址（应用层），TEI = 观测属性

广播轮无预期 TEI 名单；"该回名单"来自**下行载荷解析出的目标地址序列**（并发抄表 DATA 携带表地址序列；单表转发即 645/698 地址域）。判定规则：

```
M_req = 下行载荷解析的目标表地址集合          （该回名单）
M_rsp = 上行载荷解析的应答表地址（挂应答者TEI）  （实际回账）
没回       = M_req − M_rsp
回了但否认 = 应答帧 645 控制码异常/否认（协议一等结果，配置字含否认重试标志）——单独分类
正常       = M_req ∩ M_rsp，逐表三段证据链
```

统一适用于单播与广播（单播的目的 TEI 只是"发给哪个代理"，抄哪块表同样在载荷里）。多轮累积的 `(表地址 → 应答STA TEI)` 映射为**代理关系/户变观测**副产物。

### 4.3 轮闭合窗口

`轮闭合 = max( 下行末帧 + 设备超时×2×(最大重试次数+1) , 观测闭合：T 秒无该序号新帧 )`
——帧内参数从配置字/设备超时域读取；观测闭合 T 由 profile 缺省（建议 10s，可配置）。禁止用单表超时充当轮窗口（§3 实证 44s ≫ 5.1s）。

### 4.4 状态机

```
armed → sent(S1) → acked(S2a) → responded(S2b) → confirmed(S3: explicit_ack | no_retransmit_inference)
                ↘ retransmitted(R1..Rk，记时刻/间隔)   ↘ denied(否认)   ↘ timeout(断点=最后到达的阶段)
```

S3 每条流必须输出 `evidence_kind`，区分铁证与推断；重传序列完整保留（重传间隔是信道质量信号）。

## 5. 特征表达（AI 输入）

### 5.1 分层匹配

| 层 | 字段 | 来源 | 说明 |
|---|---|---|---|
| L0 元组 | `frm_type`、`app_id`、`app_port`、`nid`、`channel` | DLL 已解析→物化列 | SQL 精确匹配，留空=通配 |
| L1 报文头 | `msg_seq`（报文序号）、`dst_tei`/`ori_tei` | APP_RAW 按 4-3 结构表提取→物化列 | flow/round 级锁定键；campaign 级运行时分配 |
| L2 载荷 | `app_raw_contains`（hex 片段）、`app_fields`（结构化字段如表地址） | APP_RAW 内容 | 同业务内区分目标 |

### 5.2 特征 JSON

```json
{
  "scope": "round",                          // flow | round | campaign
  "window": { "mode": "live", "timeout_seconds": 180 },   // live | time_range | cursor_range（复用现有窗口语义）
  "feature": {
    "frm_type": "终端主动并发抄表",
    "app_id": "0003",
    "dst_tei": "",                           // 留空=全部对端（广播/批量）
    "msg_seq": "",                           // campaign 级留空
    "app_raw_contains": "", "nid": "", "channel": ""
  },
  "response_policy": {                       // 缺省值全部从帧内参数推导
    "timeout_ms": null, "use_ack_evidence": true, "confirm_via_0x0020": true,
    "expect_meters": []                      // 可选：显式目标名单（缺省从载荷解析）
  }
}
```

### 5.3 样例反推（feature_hint）

`GET /listener/frames/{id}` 响应增加 `feature_hint` 字段：该帧可构成的特征草稿
（frm_type/app_id/port/TEI/msg_seq/载荷片段建议 + 操作提示"去 msg_seq 升级为 campaign"）。
AI 工作流：翻帧 → 取 hint → 调整 → POST /traces。不设独立预览端点。

## 7. 架构与落点

1. **4-3 应用层解析件**（唯一新解析件）：`parser_lib` 内结构表驱动模块（逐报文 ID 声明字节布局），输入 `app_id + APP_RAW`，输出三件套：`msg_seq` / 请求目标地址序列 / 应答表地址+应答状态。一期覆盖 0x0003 并发抄表 + 单表 645 转发；**每个 ID 用真机样本单测校准**（样本中请求/响应共享前缀 `1103 0000 0102`、自控制字节分叉，作为校准锚点）。
2. **物化与回填**：frames 表增列 `app_port/app_id/msg_seq/meter_addrs(dst/ori TEI)`，幂等迁移 + 后台回填 + 局部索引（沿用 nid/frm_type 物化先例）。回放查询因此为纯 SQL 自连接（下行 ⋈ 上行：序号+表地址+时间窗）。
3. **TraceService（侦听台侧）**：单引擎双模式——
   - **回放式**：对既有索引执行关联查询，输出完整报告（历史数据即查即得，fixture 可离线全覆盖测试）；
   - **live 式**：注册特征，帧入库钩子增量匹配，trace 句柄持续更新；同一特征 JSON、同一状态机、同一输出 schema。
4. **API**：
   - 页面侧 `POST/GET /api/listener/traces[/{id}]`（建/查/列）；
   - AI 控制面 `POST /api/ai/v1/listener/traces` → **202 + operation_id**（live 与回放统一异步化，回放大索引秒级仍走异步防阻塞），`GET /operations/{id}/wait` 复用；新 scope `listener:trace`（创建），结果读取复用 `evidence:read`；resource=索引 mapping；变更审计；
   - 执行核心经 state 访问器提升注入 AI 控制面（沿用 0008 的层间进程内注入模式，不走 HTTP 回调）。
5. **文档**：docs/16 增补侦听台追踪节；ai-control-plane skill 增补步骤；DECISIONS 新 ADR。

## 9. 风险与开放项

- **结构表覆盖度**：4-3 报文 ID 数十种，一期仅 2 个 ID；提取规则框架保证增量低成本，但 campaign 级跨业务聚合（如"抄表+心跳"联合视图）不做；
- ~~字节布局校准依赖样本量~~ → **已缓解**（2026-08-29）：校准样本已入库（`samples/` 三段 2276 帧），并产出 §10 校准记录；G1 仅剩 ACK 帧源 TEI 提取一项专项校准；
- **报文序号 16bit 回绕**：窗口内按时间就近消歧；
- **CRC 坏帧口径**：空口误码帧是否计入 S1/S2，做成特征可配置（缺省不计入、单独计数）；
- **FrmType 不区分方向**：方向以 SRC/ORI_S 判定（样本中 SRC=CCO TEI 为下行），G1 校准；
- **明确不做**：CCO 日志交叉验证（CCO 侧功能）；跨业务联合视图；前端页面（可选二期）。

## 10. 校准记录（2026-08-29，样本实测）

**样本来源**：`测试文件/并发抄表-测试文件/原始报文自动保存 - 2026-06-30.txt`（537,701 帧 / 9h50m，
帧号 406727→943182，与既有索引库同源衔接）。截取三段入库 `reqs/0009-listener-flow-trace/samples/`：
A 并发抄表轮 406727-407600（874 帧）/ B 28 分钟处 701 帧 / C 5 小时处 701 帧，共 2276 帧 / 1.4MB。
DLL（GW_SMAnalysis V1.0.23）`parse_simple` 解析成功 2260 帧（失败 16 = MAC 坏帧）。

| 发现 | 数据 | 对设计的修正 |
|---|---|---|
| 报文序号**跨 5 小时不递增** | 0x0003 并发抄表在 0min/28min/5h 三段序号恒为 `0x0201`（234/134/124 帧） | 轮 = **序号 × 时间簇**（§4.1 已修正）；重传判定限定簇内；序号语义按"业务任务号"建模 |
| 上行序号确实回填下行序号 | 台区户变识别 00A1：上行 echo `0x0113`/`0x0123`（两轮），配对规则成立 | 配对键不变；但样本下行只见 0x0123——窗口边界截断需注意（G1 提取器按完整索引回放，不受样本截断影响） |
| ACK 帧 DLL 仅出 DST | ACK 帧 `SRC=null, DST=034`，ORI_S/FINL_D 均空 | S2a 证据的 TEI 提取需在 G1 对 ACK MAC 头做专项校准（或从 parse_full Detail 挖源 TEI）；设计保留 ACK 证据，标注校准项 |
| 链路层帧无 APP 字段 | 心跳/发现列表/信标/关联等 APP_RAW 为空 | 这些帧不参与应用层配对，仅作 S2a/在线名单/观测背景 |
| 坏帧率极低 | 16/2276 ≈ 0.7% | CRC 口径缺省"坏帧不计入判定、单独计数"成立 |

字节布局锚点（G1 提取器校准基准）：0x0003 请求/响应共享业务头前缀 `11 03 00 00 01 02`，
自 645 控制字节分叉（下行 `33 06`+表地址 / 上行应答码+表地址）；0x00A1 同构（`11 A1 00 00 01 23 …`）。
候选序号位 = 业务头 bytes[4:6]，G1 按 04 文档结构表逐 ID 精确定位并以本样本单测固化。
