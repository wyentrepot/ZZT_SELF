# REQS.md — 需求 0009：侦听台通信流追踪（发送→响应→接收 三段证据链）

> **状态**：✅ 设计已定稿（2026-08-29 评审通过 + 真机样本校准完成，待开工 G1）
> **依据**：Q/GDW 双模 第4-3部分（应用层）、第4-2部分（数据链路层）蒸馏文件 + 侦听台真机捕获数据实证
> **范围**：仅侦听台（空口帧）自身证据；CCO 日志口交叉验证属 CCO 侧功能，不在本需求内

## 1. 目标

让 AI 以「一次发送的特征」锁定一条通信流，自动回答三个业务问题并给出帧级证据：

1. **CCO 有没有发出去**（下行帧出现在空口）；
2. **STA 有没有收到并响应**（链路 ACK + 同报文序号上行应答）；
3. **响应有没有被 CCO 接收**（0x0020 显式确认 / 重传反证——纯空口证据）。

支持三层粒度（flow 单流 / round 轮 / campaign 批量轮）、live 与历史回放两种模式，
对账单位为**应用层表地址**（兼容广播、单播、混合并发轮）。

## 2. 已确认边界

- 判据全部来自侦听台自己解析的帧内容，不依赖 CCO 日志、不依赖任何外部名单；
- "该回名单"从广播/单播载荷里的目标地址序列解析（方案④，已否决 STA 在线名单口径）；
- 报文序号/表地址解析采用 **4-3 结构表驱动**，逐报文 ID 用真机样本校准；
- 一期业务覆盖：终端主动并发抄表（0x0003）+ 单表 645 转发；其余报文 ID 按同一框架逐个补；
- 全部测试用 fixture 索引库/假帧，不碰真实串口（0007 红线）。

## 3. 验收标准

- [ ] 对既有索引回放：给定特征 + 时间窗，返回每轮/每表的三段判定与帧级证据（秒级）；
- [ ] live 追踪：注册特征后新帧增量匹配，复用 operation 202+wait 模式；
- [ ] 广播轮：期望目标 = 载荷解析的目标地址序列，缺席/否认/正常三分类正确；
- [ ] 重传证据：同序号下行重发被记录，S3 输出标注 evidence_kind（explicit/inference）；
- [ ] AI 控制面：token+scope 鉴权、审计、特征 JSON、feature_hint 样例反推可用；
- [ ] docs/16 与 ai-control-plane skill 同步更新。
