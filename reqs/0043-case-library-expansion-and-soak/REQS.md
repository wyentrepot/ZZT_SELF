# REQS.md — 需求基线（需求 ID：0043，标题：用例库扩充与长跑验证）

> 本文件遵循「需求只追加、不覆盖」ADR 模式。
> 立项日期：2026-11-23；基线版本：**v1**。
> 依据：**REQS-0042**（黑盒用例自动运行与控制台，已打通真实台架：`meter_smoke_min` 5/5 PASS、单轮 17s、连跑两次一致）。
> 本需求做的事：**0042 打通链路之后的"重复性工作"** —— 按知识库口径补齐用例、标注可测性、做长跑与稳定性验证。
> **本需求不改四层模型**（Case/Block/Fact/Capability），不改 0042 的 API/UI 契约。

---

## 1. 背景

0042 交付后，"一条用例从触发到出结论、全程零 AI/零人工"已经成立，但：

1. 用例库里**只有组网 + 抄表**两类（`meter_daily` / `meter_first_join` / `nwk_join`，共 7 条用例、2 个方案）；
2. 知识库里还有大量场景（相位、分钟采集、升级、费控、时钟、台区识别、搜表、省份扩展……），**没有盘点、没有可测性标注**；
3. 台架"跑一次通过"≠"长期稳定"：**没有长跑/重复执行/时长验证**，也不知道哪儿会先崩。

用户的定性（2026-11-23 原话口径）：

> 「这个 req 是在你打通链路之后，做的一些重复工作，验证测试长跑用的。」
> 「测试用例的用例库让子代理去知识库里搜查，按常用，cco，sta，ecu，省份等等进行排序筛选。」
> 「今天只做组网与抄表用例。其他后续慢慢补。」

---

## 2. 目标

1. **用例库盘点与可测性标注**：把知识库里的候选用例按「常用度 / 设备域（CCO/STA/ECU）/ 业务场景 / 省份区域 / 协议」整理成清单，并**逐条标注本环境可测 / 不可测**（不可测要写缺什么：缺块、缺能力、缺硬件、缺省份环境）。
2. **按域补充用例**：优先补 `CCO` 与 `STA` 域；`ECU` 域视台架能力；省份用例单列。
3. **长跑验证**：对已打通的链路（组网 + 抄表）做**重复执行与时长验证**（至少覆盖：N 轮连跑、小时级持续、失败可复现、结论稳定），产出可读报告与证据落盘。
4. **可持续**：新增用例必须**先查知识库**（0042 D6-3 铁律），并沿用 0042 的 `plan` 步骤实例化 + `category/protocols` 分类字段。

---

## 3. 非目标

- ❌ 不改四层模型（块/事实/用例/方案边界）
- ❌ 不改 0042 的 `/api/cases/*` 契约与 UI 交互（如需扩展字段，走变更记录）
- ❌ 不做真固件烧录/激活（属 `wb-flash` / `hs-dw31-upg`）
- ❌ 不为"省份用例"去造不存在的省份环境（标注为"不可测"即可）

## 4. 需求点（编号即验收锚点）

| 编号 | 需求 | 验收 |
|---|---|---|
| CL-1 | 用例库盘点表：维度 = 常用度 / 设备域 / 场景 / 省份 / 协议，**每项带知识库出处** | 表存在且在 `reqs/0043-*/CASE-BACKLOG.md`；`grep` 抽查 10 条有出处；未找到的写「库中未找到」 |
| CL-2 | **可测性标注**：每条候选用例标 `可测` / `不可测`，不可测写缺什么 | 可测项 ≥ 80% 能落到具体块/事实；不可测项原因具体到"缺哪个块/能力/硬件/省份环境" |
| CL-3 | 新用例沿用 0042 规范：`plan` 步骤实例化、`category/protocols`、`on_fail`、等待预算 | `case_run check` problems==[]；新增用例 `show` 能看到步骤表与分类 |
| CL-4 | 按域补齐：至少各 1 条 `CCO` 域与 `STA` 域用例可跑通（真机或可解释为 blocked） | 真机跑出结论（pass/fail/blocked 任一且理由成立） |
| CL-5 | 长跑：组网+抄表链路 **≥ 20 轮**连跑，结论稳定、无内存/句柄泄漏（进程 RSS 不单调增长） | 长跑日志 + 汇总表（轮次/结论/耗时/RSS），异常轮次可定位 |
| CL-6 | 长跑：**≥ 2 小时**持续跑（可间隔执行），失败可复现、无人工介入 | 证据落盘 `data/case_runs/*` + 报告 |
| CL-7 | 每次运行落盘证据完整（沿用 0042 D4-6）：`verdict`/`params`/`decisions[]`/`interventions[]`（恒空）/`self_healed`/时间戳/台架快照 | 抽查任意 3 个 run 的 `result.json` 字段齐全 |
| CL-8 | 收敛报告：哪些场景已覆盖、哪些因环境不可测、下一批建议优先级 | `reqs/0043-*/DONE.md` 或报告文件；含下一批清单 |

## 5. 依赖与前提

- 0042 交付物：`libs/case_runner`（16 块 / 8 事实 / 7 用例 / 2 方案 + `plan` 步骤实例化 + 四态 verdict + 证据落盘）、`/api/cases/*`、用例库 UI

- 知识库：`/01-workfile-ai/04-obsidian/obsidian`（`用例库/CCO/*`、`业务层/*`、省份扩展资料）

## 6. 风险

| 风险 | 应对 |
|---|---|
| 知识库用例数量大，一次补不完 | 按 CL-1 分档（常用/CCO/STA/ECU/省份），先补"可测且常用" |
| 长跑把台架跑挂（端口/会话泄漏） | 每轮前 `probe --readonly` 自检；失败自动 `blocked` 并记证据；连续 3 轮 blocked 即停并报告 |
| 省份用例无环境 | 只登记不实施，标注"不可测（缺省份环境）" |
| 复位带来的长恢复（实测≈10 分钟） | 长跑主线用 `meter_daily`（不复位）；`meter_first_join` 单独按需 |
