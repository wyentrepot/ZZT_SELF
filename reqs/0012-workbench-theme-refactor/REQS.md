## 1. 背景与目标

用户直观反馈主题「丑」且「代码写得死」。七维度静态审计 + WCAG 对比度实测后，确认这是**同一个根因的两个切面**：

**根因**：主题系统在物理上只覆盖 3/9 的页面。代码里存在 **3 套命名体系互不兼容、主色也各不相同**的 token 方言：

| 方言 | 覆盖 | 命名体系 | 主色 |
|------|------|----------|------|
| A · 工作台 | 外壳 + 验证工作台 + 串口配置 + 工作台状态 | `--bg-page` / `--fg-default` / `--accent` | `#06b6d4` |
| B · 设计稿系 | 报文追踪 + 协议字典 + 场景脚本 + 模拟集中器 | `--bg-0..4` / `--tx-1..4` / `--ac` | `#22d3ee` |
| C · 侦听台系 | 侦听台 + 模块日志 | `--canvas` / `--panel` / `--ink` / `--cyan` | `#45e0c2` |

B/C 方言的变量定义在裸 `:root` 上，无 `.theme-*` 覆盖规则，因此**切换主题时这 6 个页面纹丝不动**，只有 header 与侧栏变色 → 视觉割裂。

**级联后果**：无分层 + 靠复制维护 → 改一点要动一片且必漏 → 用户感受到「死」。

**目标**：建成 primitive → semantic → component 三层 token 体系，让 9 个页面统一响应主题切换，并兑现 REQS-0011 与 P5 已拍板但尚未落地的设计决策。

## 4. 验收标准

**P0（本期建议先做）：**
1. `body` 背景不再使用渐变；iframe 背景不再透明，无双层渐变叠加。
2. 9 个页面全部声明 `color-scheme: dark`，原生控件（滚动条/下拉框）在深色下不再突兀。
3. `.badge.inconclusive` 使用独立紫色相，与 `.badge.run` 的琥珀色可明确区分（兑现 §4.6 铁律）。
4. 非默认主题下刷新页面无主题闪跳（head 内联脚本在首屏渲染前应用 `data-theme`）。

**P1/P2（后续）：**
5. 建成 primitive / semantic / component 三层，组件层不得直接引用 primitive。
6. 全部 9 个页面通过主题覆盖率断言：切换 `data-theme` 后 body 背景色发生变化。
7. 对比度实测 0 FAIL（P1 `contrast-v2.py` token 门禁已为 50 组 / 0 FAIL；P2 仍须对接入后的页面回归验证）。
8. 新增一套主题只需改 1 处（当前需改 3 处：CSS 选择器 / JS `THEMES` / HTML `.theme-dot`）。

## 5. 非目标

- 不改任何业务逻辑与后端接口。
- 不重构操作流程（REQS-0011 §5 已明确用户未勾选该痛点）。
- P0/P1 阶段不动页面 JS（侦听台 2135 行 / 模块日志 1130 行），迁移靠 CSS 别名层完成。
- 不做响应式重做（仅沿用现有 <860px 抽屉）。

## 6. 工程约定

- **方言别名层是过渡手段**：`compat-dialects.css` 头部须标注废弃计划与删除条件（最后一个方言引用消失即删）。
- **主题机制用 `data-theme` 属性而非 `className`**：`className` 全量覆盖会清空 `<html>` 上其他 class，且 `postTheme()` 反向读取 `className` 当 key，双向脆弱。
- **主题定义留在 CSS**：JS 只负责切换属性，不产生颜色值——保证 JS 异常时主题仍有兜底。
- **逐页 commit**：每接入一页验证一页并提交，避免长时间处于未提交状态（见 §7 R2）。
- 沿用仓库既有约定：零构建纯静态、`NoCacheHTMLStaticFiles`、JS 改动带 `?v=` 版本参数。
