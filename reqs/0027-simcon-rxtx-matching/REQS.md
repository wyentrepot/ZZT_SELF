## 1. 背景与问题

用户反馈模拟集中器页面"下发与接收不匹配给用户看"：下发一帧后只看到单帧回显，收没收到应答、应答对不对、超没超时，都要靠人翻原始帧流。代码实查三处缺口：

1. **无收发配对视图**：页面（`apps/workbench/static/pages/simcon/`）下发走 `/api/simcon/step`，返回后仅构帧预览 + 记录行；没有"我发的查询 → 收到的应答"成对呈现，更没有按帧型区分的展示格式。
2. **匹配规则无协议知识**：`libs/sim_concentrator/matcher.py` 只有通用 AFN/FN/字段匹配；不知道 1376.2 的应答规律（05H 控制类→应回 00H-F1 确认 / F2 否认；03H/10H/11H 查询设置类→应回同 AFN 同 Fn 数据帧）。否认码 6D/6E/6F（109 超最大并发 / 110 超条数 / 111 正在抄读中）无语义翻译，页面上只显示 hex。
3. **超时一刀切 5 秒**：`runner.py` 的 `expect_timeout=5.0` 对所有 Fn 统一适用；而蒸馏出的真实业务口径是单抄 59s、并抄 99s、重发间隔 6500/14000/18000/25000ms——选并发抄表时页面 5 秒即报"等待帧超时"，是假超时。

## 2. 目标（G1-G3）

| # | 目标 | 内容 |
|---|------|------|
| G1 | 收发配对可视化 | 下发后在页面呈现"下发帧 ↔ 应答帧"配对卡片：左侧下发（AFN/Fn/参数摘要/构帧 hex），右侧应答按帧型分格式渲染——①查询类（03H/10H 系）解析成数据表格（沿用 resp-grid 思路）；②控制类（05H）渲染确认帧/否认帧徽标（否认附 6D/6E/6F 人话：超最大并发/超条数/正在抄读中）；③设置类（11H）确认徽标 + 生效参数回显；④嵌套 645/698 帧按现有解码展示。等待中显示倒计时，超时显式标注"预期应答未到" |
| G2 | 应答预期规则库（AFN/Fn→应答形态映射） | 新增声明式映射表（随 profile 或独立 JSON）：每条 = 下行 AFN/Fn → 预期应答 {afn, fn, dir:"up", 形态: confirm/deny/table} + 否认码集合 + 判定人话模板。step 接口用它自动生成默认 expect（现有显式 expect 可覆盖），并把 match 的 reasons 翻译成中文。串口上非预期帧标记"旁听"单独归类，不占匹配窗口 |
| G3 | 业务化超时与重发窗口 | per-Fn 超时档位表：查询/确认类默认 5s；抄读类按蒸馏口径（单抄 59s、并抄 99s）；页面按所选 Fn 自动取档（可手动覆盖），等待期间显示倒计时/进度；支持在窗口内持续等待应答而非一次性 recv（与 runner expect_history 轮询语义对齐）。超时门限在 UI 标注出处（蒸馏/代码实测值） |
| G4 | 统一抄读数据表格 + 成功率 | 分钟采集、并发抄表等批量抄读的所有回数据汇总进一张统一表格（列：表地址/抄读方式 AFN-Fn/数据项/值/时间/耗时/结果状态），顶部统计行：下发数/应答数/成功数/失败数/**成功率**、失败按否认码细分（6D/6E/6F/超时/无应答）。表格支持按方案/时间段/结果筛选；单抄与并抄共用同一表格，附来源标记 |
| G5 | 并发抄表滑窗调度（最大并发保持） | 新增并发抄表任务模式：①**最大并发数可配**（默认档位 + 页面可调；上限口径参考 CCO 侧 aps_max_trans 与蒸馏事务框架，拒绝码 6D=超最大并发）；②滑窗调度——每收到一个应答（成功或失败即槽位释放）立即补发队列中下一块表，始终保持在途数=最大并发，直至队列发完；③表格实时滚动追加 + 在途/已完成/排队计数条；④每块表独立套用 G3 超时档位与重发窗口，超时释放槽位并计入失败 |
| G6 | 主动上报/事件分类型表格 | AFN=06H 主动上报按类型分表展示：①停复电事件（F5、协议类型=04H）单独一表（表地址/事件类型 停电·复电/时间/延迟）；②从节点信息上报（F1/F4）、抄读数据上报（F2）、路由工况变动（F3）、从节点事件（F5 其他类型）各归其类；每表头部显示**数量**统计，页签或分组切换；事件时间线与计数卡置顶 |

## 变更记录

### 变更 2 ｜ 2026-09-05 ｜ 王瑜
- **改成什么**: 扩展基线新增三个目标——G4 统一抄读数据表格+成功率统计（分钟采集/并发抄表/单抄共用一表，失败按否认码细分）、G5 并发抄表滑窗调度（最大并发数可配，回一帧补一发保持在途=最大并发，槽位随应答/超时释放）、G6 主动上报分类型表格+计数（停复电单独一表，F1-F5 各归其类）。
- **为什么**: 用户补充：①所有抄读数据要汇总一个表格并列出成功率；②并发抄表要加最大并发数，且回来一个就下发下一个、保持最大并发；③主动上报/停复电/事件上报要按类型分表并显示数量。
- **影响**: G4/G6 主要是前端表格 + api 汇总结构；G5 涉及 runner 新增任务模式（滑窗调度器）与 api 的任务级会话，为本次最大增量；阶段划分调整见 TODO v2。
- **被取代**: 变更 1 中"只优化单步下发/应答、不动编排"的范围表述——G5 引入了任务级会话，但场景脚本（scenario 文件编排）仍不动。

### 变更 1 ｜ 2026-09-05 ｜ 王瑜
- **改成什么**: 创建需求基线 v1——G1 收发配对可视化（按帧型分格式：表格/确认/否认）、G2 应答预期规则库（AFN/Fn 映射 + 否认码人话 + 旁听归类）、G3 业务化超时（单抄 59s/并抄 99s 档位 + 倒计时）。
- **为什么**: 用户反馈模拟集中器页面下发与接收不配对展示、缺按帧型的结果表格、超时机制不符合并发抄表等真实业务口径；经代码实查确认三处缺口（无配对视图 / matcher 无协议知识 / expect_timeout 全局 5s）。
- **影响**: 新建 `reqs/0027-simcon-rxtx-matching/`；REQS-INDEX.md 登记；simcon 库新增 expect_rules、runner/matcher/api 与前端双副本改动；不动 responder/frame_codec。
- **被取代**: 无（首版）。
