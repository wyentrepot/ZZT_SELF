# 国网 HPLC 解析工具：任务交接需求与进度表

> 文档用途：用于项目交接。接手人员可先按“运行入口”启动工具，再按“当前问题”和“待提供资料”继续完善并发抄表帧解析。
>
> 更新时间：2026-08-02

## 1. 项目目标

将国网侦听台日志解析能力封装为本地 Windows 工具：

- 使用 `GwHPLCAnalysis.dll` 解析国网帧；
- 支持数百 MB 日志文件按流读取和建立索引；
- 网页端按页查看每一帧的轻量摘要；
- 点击具体帧后，再调用 DLL 展示完整解析过程；
- 为后续日志流接入预留“索引、分页、按需详情”的处理方式。

## 5. 运行入口

### 正式模式

运行根目录的 `启动解析工具.bat`：

1. 启动本地服务 `http://127.0.0.1:8765/`；
2. 在网页输入日志完整路径；
3. 点击“建立解析索引”；
4. 从左侧分页表中点击具体帧查看详情。

### 测试模式

运行根目录的 `启动解析工具-测试模式.bat`：

- 自动加载 `hplc_web/tests/data/gw_log_sample.txt`；
- 不访问用户的数百 MB 原始日志；
- 适合验证网页、分页、详情和启动流程。

## 6. 当前已知问题

### 6.1 并发抄表帧解析仍不完整

当前 DLL 已能进入“终端并发抄表”相关分支，但真实报文中的 MPDU 字段仍需要和协议原文逐字段核对。重点关注：

- 应用层类型和业务类型的判定；
- 并发抄表数据单元的数量及循环结构；
- 每个数据单元的终端地址、对象标识、数据长度和数据值；
- 请求帧与响应帧之间的序列号、地址和业务关联；
- 长度字段、分片/拼接和校验字段的边界。

### 6.2 测试样本中存在 DLL 摘要异常

开发样本共 300 帧，索引不会丢弃异常帧；部分帧的 DLL 简单解析返回错误或不完整结果。异常帧仍保留原始十六进制内容，可以点击逐帧查看完整结果。

这类“解析异常”不能直接等同于“原始帧错误”，需要结合 MPDU 长度、帧类型和协议定义判断。

### 6.3 大文件使用边界

- 不要把完整日志粘贴到聊天中；
- 不要反复读取原始大文件做试验；
- 需要分析时先截取有限行数/有限字节的样本；
- 真实验收建议按时间段或帧序号做小范围抽样。

### 6.4 抄表帧 Python 富化未对接（2026-08-02 发现）

**问题描述**：DLL 已能对抄表帧（0x0001 终端主动抄表 / 0x0002 路由主动抄表 / 0x0003 终端主动并发抄表）输出 `APP_PORT/APP_ID/APP_RAW`（`intf.cs` 602-606 行）并识别 `FrmType`（`hplcFrame.cs` 6641-6655 行）；Python 侧 `DualMode43Adapter._parse_meter_business` 也已实现抄表报文头部解析和 DATA 区递归（`parser_lib/adapters/adapter_dualmode/__init__.py` 237-307 行）。但 `hplc_web/application_service.py::enrich_summary` 只对 `APP_ID ∈ MINUTE_TYPES`（00E2/00E3/00E4）路由到 Python 适配器，**抄表帧（0001/0002/0003）直接返回 DLL 原始摘要，MPDU 数据区（内嵌 645/698 帧）未在网页详情中展示**。对应 R-06。

## 12. 2026-08-02 会话补充：分钟采集分析

本期新增分钟采集报文（`0x00E2` / `0x00E3` / `0x00E4`）的识别、持久化与周期统计，验收输入为 `测试文件/测试文本.txt`（50 条记录）。

### 12.1 识别规则（E2/E3/E4）

- 分类依据是**有界 APS 应用层报文头**：`APP_PORT == 0x11` 且报文 ID（little-endian）为 `0x00E2/0x00E3/0x00E4`；**禁止**按字节串 `11 E4` 搜索报文其他位置。
- DLL（`GwHPLCAnalysis.dll`，V1.0.23+）负责 sniffer 信封、FCH、MAC、TEI 与精确 APS 边界，简单摘要新增三个字段：
  - `APP_PORT`：端口号，两位大写十六进制（如 `11`）；
  - `APP_ID`：报文 ID，四位大写十六进制（如 `00E4`）；
  - `APP_RAW`：有界应用字节（自端口字节起，紧凑大写十六进制），边界非法/越界时为 `null`，不复制物理块补齐字节。
- Python `DualMode43Adapter`（`parser_lib/adapters/adapter_dualmode/`）只消费 `APP_RAW`，解出结构化分钟字段并递归 645/698：
  - `0x00E2` 采集任务配置：业务头 16 字节（含目的 MAC、任务号、协议类型、表类型、采集周期、数据项）；
  - `0x00E3` 采集任务数据读取：业务头 20 字节（含协议类型、电表类型、目的 MAC、任务号、冻结时刻）；
  - `0x00E4` 采集任务数据上报：主动上报格式业务头 8 字节（报文头长度 8、方向上行、启动位 1、报文序号 32bit、转发报文长度 16bit），转发报文含 `前导字段`、源 MAC、任务号、协议类型、电表类型、响应结果、冻结时刻、上报数量、数据长度，数据区内递归解出内嵌 645/698 帧；`try_extract` 按 `4 + 报文头长度 + 转发报文长度` 完整消费，不停在第一条内嵌帧。
- **未解析字段 `前导字段`**：真实样本中源 MAC 之前存在 1 个未在《分钟采集应用帧格式介绍.md》文档化的字节（如 `01`），本期按“前导字段”原样展示，命名与含义待后续协议文档确认后修正。

### 12.2 聚合语义（周期统计）

- 建索引时把 `APP_ID == 0x00E4` 的上报写入 SQLite 表 `minute_reports`（与 `frames` 同建同删），列：`frame_id, log_time, time_seconds, cco_tei, station_key, source_mac, source_tei, task_no, protocol_type, meter_type, response_result, freeze_time, report_count, data_length, application_error`。
- CCO 归属：`FINL_D == "001"`（缺省时回退 `DST`）；站点身份：源 MAC 优先，回退 `ORI_S`、再 `SRC`。
- 默认周期 15 分钟、按时钟边界对齐；时间解析 `HH:mm:ss.fff` 转毫秒，时间回退超 12 小时按日偏移累加。
- 去重：每周期每站点计 1 次（`deduplicate=true` 时展示数 = 唯一站点数；`false` 时 = 原始帧数）。原始数、重复数、解析异常数始终保留。
- 成功/失败/解析异常互斥计数：`application_error` 非空记解析异常；否则 `响应结果 == 0` 记成功、非 0 记失败。

### 12.3 接口与页面

- `GET /api/logs/minute-analysis?period_minutes=15&cco_tei=001&deduplicate=true`
  - 参数：`period_minutes`（1..1440，默认 15）、`cco_tei`（3 位大写十六进制，默认 `001`）、`deduplicate`（默认 true）；非法值返回 HTTP 422。
  - 响应：`periods`（每周期：`period_start/end`、`raw_report_count`、`unique_station_count`、`duplicate_count`、`success_count`、`failure_count`、`parse_error_count`、`report_count`、`station_keys`、`frame_ids`、`description`）、`summary`（周期数、原始上报、STA-周期去重数、重复数、成功、失败、解析异常）、`filters`。
  - 周期详情可回溯到全部原始帧 ID，重复站点仍保留全部证据帧。
- 页面新增「分钟采集分析」tab：周期选择器（默认 15）、CCO TEI 输入（默认 `001`）、去重复选框（默认启用）、汇总卡片、周期表（周期/去重上报STA数/原始帧数/重复数/成功/失败/解析异常/简介），点击周期行展开站点列表与证据帧链接（链接复用现有帧详情面板）。

### 14.4 使用说明

1. 点击「选择文件…」按钮弹出 **Windows 原生文件选择对话框**（由后端同机进程调用 tkinter 弹出，直接拿真实路径，文件内容不经浏览器）；
2. 若需在服务器目录树中定位，点击「浏览目录」打开自定义对话框（盘符快捷入口/双击目录进入）；
3. 单击文件选中、双击直接回填到路径框并关闭；
4. 原生对话框默认定位到上次成功打开的日志所在目录。

> 补充说明：浏览器网页本身受安全沙箱限制拿不到服务器磁盘路径（`<input type="file">` 只返回 `fakepath`），故原生对话框由后端进程弹出；这也避免了大文件（如 303MB 原始日志）经浏览器上传的开销。
